# tos 테스트 트리 mypy 래칫 계획 (유예 10종 해소)

- 작성일: 2026-09-18
- 성격: 실행 계획 (비규범). 게이트 강화 순서와 PR 단위를 정한다.
- 선행: PR #742(테스트 트리 mypy 결선) · PR #743(Black 커버리지 + 순서 주장 정정)
- **측정 시점: main `104fce1a`** — 이 문서의 모든 수치는 그 커밋에서 잰 것이다.
  main 이 움직이면 낡는다. 재실행 방법은 §1.2 에 있다.

## 0. 왜 이 문서가 있는가

PR #737 에서 테스트 **헬퍼**의 타입 결함(한 이름을 두 타입으로 재대입 — 단언을
무력화할 수 있는 자리)이 **리뷰 3라운드와 CI 3회를 전부 통과**했다. 원인은
`tos-firewall` 의 mypy 가 `src` 만 보고 두 테스트 트리를 보지 않은 것이었다.

PR #742 가 그 구멍을 닫았다. 다만 기존 부채가 커서 통째로 넣을 수 없었고, 두 가지
방식을 검토하고 **버렸다**:

| 버린 방식 | 이유 |
|---|---|
| 파일 단위 예외 목록 | 이 저장소가 이미 당한 **「레지스트리 + 고정 안 된 위성」의 재생산**. 새 파일이 조용히 미커버로 합류한다 |
| 베이스라인 에러 카운트 래칫 | 리뷰 규약 §5 가 금지한 **fingerprint** |

채택한 것은 **에러 코드 단위 유예**다. 코드 목록은 유한하고, 파일이 늘어도 썩지
않으며(새 파일은 생긴 순간부터 켜진 모든 코드로 검사된다), **줄어들기만 한다.**

#742 가 9종을 켰다(`assignment` · `method-assign` · `dict-item` · `str-bytes-safe` ·
`type-var` · `call-arg` · `call-overload` · `list-item` · `var-annotated`).
**이 문서는 남은 10종을 어떤 순서로 켤 것인가를 정한다.**

### 1.2 재측정 방법

```bash
# 대상 코드 하나만 켜고 나머지 9종은 유예한 채 재는 스크립트.
all=(arg-type no-untyped-def attr-defined return-value no-any-return \
     unused-ignore union-attr operator index misc)
for tree in tos/tests tos/runtime/tests; do
  for target in $all; do
    flags=()
    for c in $all; do [[ "$c" == "$target" ]] || flags+=(--disable-error-code=$c); done
    mypy $tree --ignore-missing-imports --no-error-summary "${flags[@]}" \
      | grep -c "\[$target\]"
  done
done
```

**두 함정을 피해야 한다** — 둘 다 이 측정을 실제로 틀리게 만들었다:

1. **플래그를 변수에 담아 `$VAR` 로 넘기지 말 것.** zsh 는 따옴표 없는 변수를 단어
   분할하지 않아 플래그 10개가 **인자 하나**로 전달되고, mypy 는 `Invalid error
   code(s)` 로 즉시 죽는다. 위처럼 **배열**을 쓴다.
2. **`2>/dev/null` 로 stderr 를 가리지 말 것.** 위 죽음이 가려진 채 `grep -c` 가 0을
   돌려주면 **「비용 0」으로 읽힌다.** 실제로 그렇게 읽고 보고할 뻔했다.
3. 두 트리를 **한 명령으로 합치지 말 것** — `mypy tos/tests tos/runtime/tests` 는
   `Duplicate module named "tests"` 로 중단되어 사실상 아무것도 검사하지 않는다.

## 2. 핵심 발견 — 코드끼리 간섭하지 않는다 (`unused-ignore` 하나만 빼고)

각 코드의 한계비용이 **전체를 켠 수치와 전부 같았다.** 유일한 예외가
`unused-ignore` 로, 전체 기준 53 대 한계 **283** 이다.

이유는 `unused-ignore` 만이 **다른 코드가 켜져 있는지에 의존**하기 때문이다.
`# type: ignore[arg-type]` 은 `arg-type` 이 꺼져 있으면 「불필요」로 보인다. 지금
green 을 만들자고 지우면 **나중에 `arg-type` 을 켤 때 필요한 억제를 미리 없애는
것**이라, 래칫을 쉽게 만드는 게 아니라 어렵게 만든다.

두 가지 결론이 따라온다:

- **순서를 고민할 필요가 없다.** 어떤 코드를 먼저 켜도 다른 코드의 비용이 변하지
  않는다. 비용과 신호만 보고 고르면 된다.
- **`unused-ignore` 는 반드시 마지막이다.** 그것은 다른 코드들을 **재는 도구**이지
  앞장서는 코드가 아니다.

정정 이력: PR #742 는 「다음에 켤 코드는 `unused-ignore`(53건)」라고 적었다. 위
이유로 **틀렸고**, PR #743 이 정정했다.

세부는 **집합 차로만** 말한다(아래 두 수는 `comm` 으로 잰 것이다):

| 갈래 | 건수 | 뜻 |
|---|---|---|
| 전체를 켜도 unused | **53** | 유예와 무관하게 **죽은 억제**. 283의 완전 부분집합이다 |
| 유예 때문에만 unused | **230** | 유예 코드의 에러를 실제로 억제 중 — 지우면 안 된다 |

**이 53건은 지금 당장 치울 수 있고, 치워야 한다.** 유예 상태와 무관하게 아무것도
억제하지 않는 `# type: ignore` 이고, **바로 그것이 이 아크에서 두 번 우리를 문
부류**다(PR #737 의 헬퍼, 그리고 `test_adapter.py` 의 죽은 `ignore[attr-defined]`
10곳 — 실제 에러는 `assignment` 였다). §3 의 어느 단계와도 독립이므로 **1단계에
얹거나 별도 소형 PR로 처리한다.**

이 문단의 이전 판(「228건 직접 일치 + 2건 캐스케이드」)은 **저자가 재지 않고 다른
리뷰의 표본을 옮겨 적은 것**이라 재현되지 않았다. 억제 코드 텍스트를 파싱해 원인을
1:1로 귀속하는 분해는 혼합 코드(`# type: ignore[call-arg, arg-type]`)와 캐스케이드가
섞여 신뢰할 수 없다 — **집합 차만 쓴다.**

## 3. 계층과 순서

### 3.1 1단계 — 한 PR (113건 / 약 46파일)

`misc` + `index` + `operator` + `union-attr`.

묶는 근거: 비용이 작고 파일이 집중돼 있다. **`union-attr` 43건은 전수가**
`Item "None" of "X | None" has no attribute` — 100% None 안전성이다. `operator` 는
28건 중 **21건**이 `Unsupported operand types for + ("None" and "int")` 류이고
**7건은 `"object" not callable`** 로 성격이 다르다. `index` 는 사실상 두 파일
(`test_evidence_scrub.py` 15 · `test_file_custody.py` 6)이고, `misc` 는 19/20 이
제너레이터 반환형 애노테이션이라 기계적이다.

넷에 **§2 의 「전체를 켜도 unused」 53건**을 얹는 것을 권한다 — 유예와 독립이고,
치우면 죽은 억제가 사라진다.

넷을 한 PR로 묶는 것이 §5 의 「PR 하나에 코드 하나」와 어긋나 보이지만, 합쳐도
113건이고 넷 다 같은 성격(좁은 지역 수정)이라 리뷰가 형식이 되지 않는다. **묶어서
리뷰가 어려워지면 쪼갠다** — 판단은 리뷰어 몫으로 남긴다.

### 3.2 2단계 — 개별 PR (304건)

`no-any-return`(55) → `return-value`(116) → `attr-defined`(133) 순. 작은 것부터
간다.

`attr-defined` 133건 중 23건은 `"AST" has no attribute "lineno"` 로 mypy 의 `ast`
유니온 처리 한계에서 온다. **운영자 처분(§6 ③): 타입 좁히기로 정면 처리한다** —
`isinstance` 분기 또는 정확한 ast 노드 타입 명시. **예외 축을 만들지 않는다.**

### 3.3 3단계 — `arg-type` 833

**성격을 실측으로 규정한다**(833건 전수 패턴 매칭):

| 패턴 | 건수 | 무엇 |
|---|---|---|
| `**dict` kwargs 언패킹 | **443 (53%)** | 헐겁게 타입된 dict 를 펼쳐 넣는다. 그중 114건만 `_*_strategies.py`/`_fixtures.py`/`conftest.py` 이고 **나머지 329건은 테스트 파일 본문** |
| `None`/`Optional` 불일치 | 112 | `operator`/`union-attr` 와 같은 None 안전성 계열 |
| 커스텀 더블(`_Stub*`/`_Fake*`/`_Mutable*` …) | **77 (9%)** | 더블이 Protocol 을 만족하지 않음 |

**저자의 초기 규정(「테스트 더블이 Protocol 미충족 — PR #742 의 `SealLookup` 과 같은
뿌리」)은 틀렸다.** 그 진단은 **9% 에만 맞는다.** 저자가 고른 표본 4건이 전부 더블
사례였던 탓이고, fact-check 가 더 넓게 표본해 잡았다. 지배적인 것은 **kwargs 언패킹**
이며, 이는 더블 계약 문제가 아니라 **팩토리·전략 헬퍼와 호출부의 타이핑 문제**다.

**집중도가 높다** — `test_brokercap_routing.py` 한 파일이 443 중 **96건**(22%)이다.
분할 축은 도메인이 아니라 **패턴 + 상위 파일**이 될 가능성이 크다.

세 가지를 못박는다:

- **77건(더블)에 대해서만**: 더블이 계약을 지키게 고친다. **Protocol 을 넓히지
  않는다.** 느슨하게 만들어 green 을 얻으면 프로덕션 타입 안전성을 테스트 편의로
  팔아먹는 것이다.
- **443건(kwargs)에 대해서는 다른 처방이 필요하다.** 팩토리 반환형을 좁히는 것이
  근본이고, 호출부마다 캐스트를 박는 것은 인스턴스 처방이다 — **어느 쪽인지 별도
  계획에서 정한다.**
- **한 PR로 하지 않는다.** 833건 단일 diff 는 리뷰가 형식이 된다.

이 단계는 **착수 전 별도 계획을 쓴다** — 위 세 패턴의 처방이 서로 다르고, 분할 축도
실측으로 정해야 한다.

### 3.4 마지막 — `unused-ignore`

§2 의 이유로 맨 끝이다. 앞 단계가 진행될수록 이 수치는 **저절로 줄어든다** — 283
중 230건이 「유예 때문에만 unused」이므로, 그 유예가 걷힐 때마다 해당 ignore 는 다시
「사용 중」이 된다. 마지막에 재면 남은 것이 진짜 죽은 억제다.

단, §2 의 **53건은 기다릴 이유가 없다** — 유예와 무관하게 죽어 있으므로 1단계에서
치운다.

## 4. 하지 말 것을 권하는 것 — `no-untyped-def` 623

**`check_untyped_defs = true` 가 이미 `pyproject.toml:318` 에 켜져 있다.** 즉
**애노테이션 없는 함수의 본문도 이미 검사되고 있다.** 실측으로 확인했다 —
`--check-untyped-defs` 를 명시로 켜도 `arg-type` 이 324 로 **변하지 않는다**.

따라서 623개 함수에 애노테이션을 채워도 **탐지력이 거의 늘지 않는다.** 스타일이지
안전성이 아니다. 그리고 623건/183파일 diff 는 의미 있는 리뷰가 불가능해, 이 저장소가
싫어하는 **형식적 승인**을 부른다.

**다만 선언과 게이트가 어긋나 있다** — 같은 `pyproject.toml:316` 이
`disallow_untyped_defs = true` 를 선언한다. 의도는 애노테이션을 요구하는데 게이트는
유예하고 있다. **운영자 결정 사항으로 남긴다**(§6 ①). 선언을 지키기로 한다면
codemod 로 일괄 처리하되 **「리뷰 가치 없음」을 PR 에 명시**하는 것이 정직한
방식이다 — 읽지 않은 것을 읽은 척하지 않는다.

## 5. PR 당 실행 규약

#742·#743 을 믿을 만하게 만든 것을 그대로 쓴다.

1. **PR 하나에 코드 하나**(1단계의 묶음은 §3.1 의 예외). 되돌릴 수 있는 단위로.
2. 고친 뒤 **`.github/workflows/tos-firewall.yml` 의 두 mypy 스텝에서 그 코드를
   유예 목록에서 제거**한다. 고치기만 하고 게이트를 안 켜면 다음 회귀를 못 막는다.
3. **CI 명령을 그대로 로컬에서** 돌린다(워크플로에서 복사). 플래그를 변수에 담지
   말고 stderr 를 가리지 말 것(§1.2).
4. **새로 켠 코드가 실제로 red 를 내는지 뮤테이션으로 증명한다.** 저장소 안 실파일에
   위반을 심어 CI 명령이 red 인지 확인하고 원복한다. **이것이 없으면 게이트가 있는
   척만 하는 것**이고, #742 가 신뢰받은 이유가 이것이다.
5. **켜기 전후 한계비용을 PR 에 기록**한다. 래칫이 읽혀야 다음 사람이 이어받는다.
6. 리뷰는 **저자와 다른 패스**로 띄운다(`model: sonnet` 명시). 판정은 머지 전에 PR
   코멘트로 남긴다 — 지적 0건이어도.
7. **테스트 수 불변을 확인**한다. `pytest` 에 **`-q` 를 붙이지 말 것** —
   `pytest.ini` 의 `addopts` 에 이미 있어서 또 붙이면 quiet 2단계가 되어 「N passed」
   요약 줄 자체가 사라진다(이 아크에서 여러 에이전트가 그 때문에 dot 을 셌다).

①의 뜻을 정확히 적는다 — **`disallow_untyped_defs = true`(`pyproject.toml:316`) 선언은
그대로 두되 게이트는 유예를 유지한다.** 선언을 내리지도, 623건을 채우지도 않는다.
의도(애노테이션을 요구한다)와 집행(지금은 강제하지 않는다)이 **의도적으로** 어긋난
상태이며, 그 이유는 §4 에 있다 — `check_untyped_defs` 가 이미 켜져 있어 채워도 탐지력이
거의 늘지 않는다. **이 어긋남을 발견한 사람이 「버그」로 읽지 않도록 여기에 못박는다.**

③의 뜻 — 예외 축을 설계하는 대신 `isinstance` 분기나 정확한 ast 노드 타입 명시로
**실제로 고친다.** 예외는 다음 사람이 같은 판단을 다시 하게 만들고, 그 판단이 파일
목록으로 흐르기 쉽다(§0 이 버린 것).
