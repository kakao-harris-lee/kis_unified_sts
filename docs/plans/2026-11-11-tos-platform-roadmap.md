## 0. 원칙 — 모든 단계가 지킨다

1. **전략은 tenant 설정이다.** 진입·청산 규칙, 지표 선택과 파라미터, 수량, 시간창은 모두
   `config/tos_runtime/<tree>/` 아래 YAML 이다. **전략마다 파이썬 모듈을 만들지 않는다.** «임시로»도 만들지 않는다.
2. **코드는 플랫폼에만 둔다.** 커널(`tos/`), 런타임(`tos/runtime/`), 생산자(`tools/tos_cp3/`), 그리고
   **수가 정해지고 버전이 매겨진 지표 카탈로그**. 카탈로그에 지표를 더할 때만 코드 리뷰가 필요하다.
3. **돈을 다룬다 → 회귀 최소화가 기본이다.** 플랫폼 코드 변경은 그 동작을 고정하는 테스트와 함께 들어온다
   (§6). 선언형 변경(tenant YAML)은 리플레이 정답 비교로 검증한다(P3). 테스트를 줄여서 일정을 맞추지 않는다 —
   완화는 측정 기준에만 한다.
4. **실전 선물 주문 경로는 영구 차단**(CLAUDE.md 비협상 규칙). 선물은 SYNTHETIC, 주식은 KIS MOCK.
   주식 실계좌는 이 로드맵 밖의 별도 권한 결정이다.
5. **심판 장치를 늘리지 않는다**(CLAUDE.md R5·R6). 새 검사는 그것이 막았을 실제 사고를 옆에 적는다.

## 2. 단계 — 순서와 완료 판정(측정으로만)

순서의 이유: **보여야 고칠 수 있고(P1), 선언형이 돼야 전략을 늘릴 수 있고(P2), 리플레이가 있어야 늘린 전략을
안전하게 바꿀 수 있다(P3).** 실행(P4)과 성과(P5)는 그 위에 얹는다.

### P0 — `TOS_PAPER_READY` (완화판) · ~11-18

완화 문서 §2 그대로. R4 프로브 진입(주식 트리 YAML)으로 MOCK 1건 관통, LONG 깨끗한 날 누적 5.
끝나면 R4 바인딩 0, B3 증인 바이트 동결이 풀린다(CLAUDE.md 「`TOS_PAPER_READY` 까지」).

### P1 — 관측: «왜 이 바에서 이 결정이었나» · 11-16 ~ 11-27

- `sts tos inspect <session> [--from HH:MM --to HH:MM]` — 바마다 한 줄: 필드값 · **규칙별·비교식별 통과/실패**
  (DSL 평가기 `eval_compare` 를 그대로 재사용 — 다시 구현하지 않는다) · 결정 종류 · 정지 단계와 사유.
  입력은 세션 `journal.jsonl` + evidence DB 읽기 전용. 출력은 표와 `--json`.
- `/tos` 페이지에 같은 데이터의 읽기 전용 패널(가격·VWAP 선 + 규칙 통과 띠 + 결정 표시). Control Plane API 에
  `/api/tos/sessions/{id}/bars` 하나.
- **완료:** 11-06 이후 주식 세션 하나를 골라 «R1 이 왜 한 번도 안 맞았나»를 이 화면만으로 답한다(어느 비교식이
  몇 % 의 바에서 막았는지). 수치 테스트: 기록된 세션 하나를 fixture 로 고정해 출력 표의 정답 비교.

### P2 — 선언형 지표 필드: 새 전략 = YAML 만 · 11-23 ~ 12-18

- **카탈로그:** `shared/indicators/engine` 의 registry/spec 위에, 생산자가 쓸 지표 id 목록을 버전과 함께 고정한다
  (예: `vwap.session`, `atr`, `zscore.vwap_atr`, `rsi`, `williams_r`, `macd`, `rolling.percentile`, 시간창).
  Setup D 의 상태형 게이트(`hi_vol`·`stall_ok`·`reversal_ok`)도 **카탈로그 지표로 이식**한다 — 전략 코드가 아니라
  파라미터를 받는 일반 지표로(예: «ATR 백분위 ≥ p», «N 바 정체 해소», «M 바 반전 확인»).
- **tenant 선언:** `config/tos_runtime/<tree>/fields.yaml` — `{name, indicator, params, scale}` 목록. 생산자는 이
  파일만 읽어 필드를 낸다. DSL 이 참조하는 필드가 선언에 없으면 **부팅 거부**(기존 `resolve.py` 바인딩 거부와
  같은 자리).
- **동등성 증명(이식의 정답):** P0 뒤 B3 증인 동결이 풀리므로, 같은 Parquet 구간에서 «레거시 클래스 구동 필드»와
  «선언형 필드»를 바 단위로 비교해 **전 필드 일치**를 확인한 뒤 생산자를 바꾼다. 일치가 안 되는 필드는 사유를
  적고 고친다 — 근사로 넘기지 않는다.
- **완료:** ① Setup D 세 트리가 `fields.yaml` 로 돌고, 기록된 20 거래일 리플레이에서 결정이 이전과 바이트 동일
  ② **두 번째 전략**(후보: 주식 RSI/Williams %R 되돌림)을 **코드 diff 0** — `config/` 아래 파일만으로 추가해
  MOCK 세션이 부팅한다 ③ 레거시 `SetupDVWAPReversion` 의존을 생산자에서 제거.

### P3 — 리플레이 검증 루프와 회귀 정답 · 12-07 ~ 12-23

- `sts tos replay --tree <tree> --from D --to D` — 커널 `tos.backtest` driver 로 tenant 를 과거 분봉 위에서
  돌린다(synthetic 체결). 출력: 결정·제안·체결·손익 표.
- **회귀 정답:** 출하된 tenant 트리마다 고정 구간(예: 20 거래일)의 결정 열을 저장소에 정답으로 커밋하고, CI 가
  같은 리플레이를 돌려 비교한다. 지표 카탈로그·생산자·DSL·커널 어느 변경이든 결정이 바뀌면 빨간불 → diff 를
  PR 에서 보고 «의도된 변경»이면 정답을 갱신한다(갱신도 PR 의 일부).
- **완료:** CI 잡 1개가 출하 트리 전부를 리플레이 비교 · tenant YAML 한 줄 변경 PR 이 결정 diff 를 자동으로 보여 준다.

### P4 — 실행 확장 (MOCK·SYNTHETIC 안에서) · 2027-01

- **포지션 상태를 capsule 에:** 보유 수량 · 진입가 · 미실현 손익(틱) · 보유 바 수를 커널이 이미 가진 증거
  (finality · RCL)에서 투영해 DSL 이 읽게 한다 → 손절·목표·시간 청산이 **YAML 규칙**이 된다. 커널 변경(A 등급).
- **수량:** `quantity_basis` 를 설정으로 — 고정 N, ATR 기반 위험 수량(카탈로그 지표 참조). 한도는 기존
  aggregate risk / action flow 정책 안.
- **여러 종목:** 주식 트리를 종목 목록에서 렌더(`scripts/tos/` 렌더 경로 재사용) — 종목 추가 = 목록 한 줄.
- **완료:** 손절 규칙이 YAML 로 선언된 tenant 가 리플레이와 MOCK 세션 양쪽에서 손절 체결을 낸다.

### P5 — 성과 측정 · 2027-01 ~ 02

- tenant·날짜별 체결·손익·승률·최대 낙폭을 evidence(finality)에서 집계해 상태판 한 칸 + `sts tos perf`.
- 리플레이(P3) 성과와 paper 성과를 같은 표에 — 둘의 차이가 체결 모델 오차다.
- **완료:** 두 전략의 4주 paper 성과가 한 명령으로 나온다. 다음 전략 선택과 주식 실계좌 논의는 이 숫자로 한다.

## 4. 하지 않는 것

- 전략별 파이썬 클래스, 레지스트리/팩토리 부활(L6·L7 에서 지운 것), «빠른 실험용» 코드 경로.
- DSL 을 범용 언어로 키우기(산술식·루프·사용자 함수). 계산은 카탈로그 지표로, DSL 은 비교·결합만.
  필요한 표현이 생기면 카탈로그에 파라미터형 지표를 더한다.
- ML/RL/TFT 런타임 재도입(CLAUDE.md).
- 실전 선물 주문, 실 증거금(비협상 규칙). 주식 실계좌는 P5 숫자를 본 뒤의 별도 운영자 결정.
