# `/tos` 운영 페이지 가독성 개선 (2026-11-25)

운영자 지시 2026-11-25: «표시된 정보의 의미를 파악하기가 어렵다. 판단 근거가 되는
여러 정보를 보여 주는 창, 선정된 주식/선물 방향성 정보, 거래 현황이 보여야 한다.»

## 1. 문제

지금 페이지는 커널 내부 값을 그대로 내놓는다.

| 구역 | 문제 |
| --- | --- |
| 상단 카드 5장 | 원장 순번·증거 키 세대 같은 내부 값. `paper` 셀 하나만 설명하면서 그 사실을 밝히지 않는다. CP-3 tenant 다섯은 없다. |
| 종목 표 | 주식 tenant 만. 차단 사유가 `STAGE_DENIED · CANDIDATE_COMMAND_CONSTRUCTION` 같은 원시 코드. |
| bars 차트 | 시간축·호버·봉별 상세 없음. 규칙이 `R1-ENTRY-LONG` 같은 식별자. 요약 표는 검증 용어(V/D/W/U, 분모, journal 대체). |
| 전체 | 용어 설명·툴팁이 없다. |

데이터는 대부분 이미 있다. bars 문서는 봉마다 지표 값, 조건별 좌·우 값과 통과 여부,
발동 규칙, 정지 설명문(`halt_detail`)을 돌려주는데 화면이 그리지 않는다. 손익·미해결
주문·상태판 이슈·규칙 설명문은 CLI 도구가 계산하고 웹으로 내보내지 않는다.

## 2. 목표 — 페이지가 답할 세 질문

1. **왜 진입했나 / 안 했나** — 조건별 통과·실패를 실제 값과 기준값으로.
2. **각 tenant 가 지금 어디에 있나** — 진입 조건에 얼마나 가까운지.
3. **무엇을 사고팔았고 결과가 어땠나** — 주문·체결·보유·손익·정지.

완료 기준(측정 가능):
- 페이지의 모든 전문 용어·규칙 식별자가 쉬운 말로 바뀌었거나 툴팁을 갖는다
  (용어 사전 한 벌, 테스트가 사전에 없는 규칙 id 를 잡는다).
- 임의의 봉 하나를 골라 «어떤 조건이 실패해서 진입하지 않았는지»를 화면만 보고 말할 수 있다.
- 다섯 tenant 모두 카드로 보이고, 주식은 오늘 실현 손익, 선물은 가상 손익이 보인다.
- 장중에 판단 근거가 5분 이내 지연으로 갱신된다.

## 3. 사실 관계가 바꾼 요구

- **«선정된 방향»은 없다.** tenant 마다 종목과 방향이 설정에 고정이다(LONG·SHORT 는 별개
  tenant, 주식은 전부 LONG). 후보 중에서 고르는 단계가 없으므로 «선정 결과» 대신
  **tenant 별 진입 근접도**(진입 조건 n/5 충족, 가장 가까운 미충족 조건)를 보인다.
- **선물은 판단 전용이다.** 운영자 결정 2026-11-05 — 선물 진입은 독립 승인 단계에서
  멈춘다(상시 승인은 모의 주식 전용). 주문·체결·보유가 없다. 결과를 보려면 §6 의
  가상 손익을 쓴다.
- **주식 거래의 대부분은 프로브다.** `R4-M2-PROBE-ENTRY-LONG` 은 Setup D 신호가 아니라
  주문 경로 시험이다(전략 YAML). 화면은 이를 «시험 진입»으로 구분한다.
- **보유는 브로커 잔고가 아니다.** 웹 계층은 KIS 를 부르지 않는다. TOS 자체 FIFO 집계임을
  화면에 밝힌다.

## 4. 화면 구성

```
① 상태 띠        지금 괜찮은가        실행 상태 · 이슈 · 깨끗한 날 · 기준 시각
② tenant 카드    각자 어디에 있나     세션 단계 · 방향 · 진입 조건 n/5 · 보유 · 손익
③ 판단 근거      왜 진입했나/안 했나  차트 · 한 줄 식 · 조건 체크리스트 · 막은 조건 · 타임라인
④ 거래 현황      무엇을 사고팔았나    주문·체결 · 보유 · 손익 · 미해결 주문
⑤ 사건 기록      무슨 일이 있었나     게이트 차단 · 보류 · KIS 오류, 쉬운 문장
⑥ 시스템 내부    (기본 접힘)          지금의 상단 카드 · 검증 요약 표
```

카드를 고르면 ③④⑤ 가 그 tenant·세션으로 바뀐다. 지난 날짜는 세션 드롭다운(#1176)으로 본다.

구역 안 규칙:
- **한 줄 식 + 체크리스트.** «진입 = 진입 시간대 그리고 변동성 높음 그리고 정체 확인
  그리고 반전 확인 그리고 z ≤ -1.8». 항마다 참·거짓, 행마다 실제 값·기준값·통과까지 거리.
- **게이트와 신호를 가른다.** 전략 조건(신호)과 커널 단계 차단(승인 없음 · 거래소 불허 ·
  보유 없음 · 시간 미인정)은 다른 줄이다. «신호 없음»과 «신호는 있었으나 차단»이 같아
  보이면 안 된다.
- **거래하지 않은 봉에도 판정을 남긴다.** «신호 없음 — 반전 확인 실패»,
  «신호 있었으나 승인 단계에서 차단». 타임라인 기본값은 판정이 바뀐 봉만.
- **두 단계까지만 펼친다.** 첫 화면은 ①②, 상세는 한 번의 선택으로.
- **색.** 빨강·파랑(`--color-profit` · `--color-loss`)은 가격·손익 방향에만. 통과·실패와
  상태는 아이콘 + 글자 + 중립·주황·경고색 하나. 색만으로 뜻을 전하지 않는다.
- **기준 시각과 구분 표시.** 카드마다 데이터 기준 시각과 MOCK · 판단 전용 · paper 표시.
- 파이·도넛·게이지 차트, 백테스트 통계(샤프 등)는 넣지 않는다.

## 5. 재사용과 기각

재사용: 기존 세 읽기 모델(`/api/tos/{projection,symbols/today,sessions,sessions/{id}/bars}`),
`tools/tos_cp3/perf.py::build_report`(export_symbols 가 이미 호출하고 손익을 버린다),
`tools/tos_cp3/status_board.py::build_board`, 전략 YAML 의 `rationale:` 와 `fields.yaml`,
손으로 그린 SVG 차트, `globals.css` 의 손익 토큰.

| 기각한 안 | 이유 |
| --- | --- |
| 차트 라이브러리 도입 | 봉 400개 선 차트 하나에 의존성을 들일 이유가 없다. 기존 SVG 에 축·호버만 더한다. |
| 대시보드가 증거 DB 를 직접 읽기 | `services/` 는 `tos`·`tools` 를 import 하지 못한다. 파일 문서를 사이에 둔 지금 구조를 유지한다. |
| 웹에서 KIS 잔고 조회 | 읽기 전용 표면에 자격증명을 들이게 된다. 잔고 대조는 `mock_flat_check` 가 한다. |
| 선물에 자동 승인 허용(가상 거래소 체결) | 11-05 결정을 뒤집고 주문 수명 주기 전체를 선물에서 다시 검증해야 한다. 가상 손익으로 목적이 충족된다. |
| 여러 페이지로 분리 | 운영자 한 명, 질문 세 개. 한 페이지 + 접힘이 낫다. |

## 6. 단계

각 단계가 PR 하나다. 등급은 전부 B(읽기 전용 운영 표면), 독립 리뷰 1회.

**P1 — 화면만, 이미 있는 데이터로.** `strategy-builder-ui/src/app/tos/` 재구성.
여섯 구역, 용어 사전·툴팁 프리미티브, 봉 선택 체크리스트와 한 줄 식, 막은 조건 막대,
판단 타임라인, 게이트 줄, 사건 기록 문장화, 지금 상단 카드를 ⑥ 으로. 손익·이슈·깨끗한
날은 자리를 만들지 않고 P2 에서 넣는다(가짜 숫자 금지).

**P2 — 내보내기 확장.** 새 데이터는 «호스트 내보내기 → `paper-projection/` 문서 →
pydantic DTO → TS 타입» 한 길로만 들어온다.
- `symbols/today.json` 에 종목별 `pnl` 블록(실현 손익 · 왕복 · 승 · 미해결 주문 요약).
  `perf` 의 `leaves[]`(계좌·경로 포함)는 내보내지 않는다.
- 선물 tenant 요약을 같은 문서에(지금은 주식 glob 만).
- 상태판 문서 신설: tenant 별 세션 상태, 이슈 목록(확인/막힘 + 문장), 깨끗한 날 누적.
- bars 문서에 규칙 `rationale`, 필드 정의, 프로브 여부. 프로브 표시는 YAML 산문이 아니라
  전략 YAML 의 명시 필드로 한다.
- **선물 가상 손익.** 진입 판단 봉의 종가에 들어가 다음 청산 판단 봉의 종가에 나왔다고
  보고 계산한다. 수수료·슬리피지 없음, 체결 보장 가정. 화면 표기는 항상
  «가상 손익(체결 가정)»이고 실현 손익과 합산하지 않는다.

**P3 — 장중 갱신.** bars 문서를 장중 5분마다 내보낸다(지금은 세션 종료 때 한 번).
`export-symbols` 의 기존 cron·flock 틀에 얹는다. 도는 세션의 증거 DB 를 읽기 전용으로
여는 비용과 1.2 MB 문서 5종의 쓰기 시간을 먼저 재고, 5분 주기가 안 되면 주기를 늘린다.
BarsPanel 에 갱신 주기를 준다.

## 7. 제약

- 대시보드 표면은 `/api/tos/*` · `/health` · OpenAPI 뿐이고 읽기 전용이다. 명령 버튼을
  만들지 않는다.
- 페이지는 Cloudflare Access 뒤에서 인터넷에 열려 있고 앱 자체 인증이 없다. 문서에 호스트
  경로·계좌 번호를 싣지 않는다.
- 모든 값은 nullable 이고 없으면 «알 수 없음»이다. 없음을 «이상 없음»으로 그리지 않는다.
- 계약 테스트: DTO 의 모든 잎이 `src/lib/dashboard/tos.ts` 에 있어야 하고, 사유 접두
  fixture 마다 `*State` 분기가 있어야 한다.
- 증인 동결(`shared/decision/setups/vwap_reversion.py`)과 수입 방화벽은 건드리지 않는다.
