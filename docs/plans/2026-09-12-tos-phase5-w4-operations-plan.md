## 2. 결정

1. **backup 은 파일 셋 + 정지 상태**: `tos_runtime/operations/backup_set.py` — `backup_set(paths: DurableSetPaths, dest_dir, generation) -> BackupSetManifest`. 저장소가 **닫힌** 상태(ControlledShutdown 후 또는 런타임 미가동)에서만 실행(열린 라이브 커넥션과의 쓰기 경합 회피 — 가동 중 백업은 §6 ⑦ 후속). 각 파일은 새 읽기 커넥션으로 `sqlite3.Connection.backup`(raw copy 금지 · `evidence/backup.py:103` 관용구 재사용). 매니페스트 = `{generation, created_at_monotonic_ns, files: {name: {path, file_digest, last_seq|None}}, evidence: {last_seq, chain_digest, key_generation}, rcl: {last_seq, writer_epoch}, inbox: {last_seq, unconsumed_count}, runtime_identity|None}` · JSON · 세대는 호출자(운영자 CLI) 지정 · **단조 증가 강제**(기존 최고 세대 이하 = 거부). 삭제 0.
2. **restore 는 항상 non-live, drill 은 복원본 위 재구성**: `restore_set(manifest_path, dest_dir) -> RestoredSet(non_live: Literal[True])` — 파일별 digest 대조 실패 = 거부 · evidence 는 기존 `evidence.backup.restore()` 경로 재사용(`verify_or_raise`). `restore_drill(...)`: 복원 디렉터리 위에 `compose_paper_runtime(environment_label=<non-live 라벨>)` 재구성 → (a) `replay_engine(restored_evidence, restored_inbox, build_core)` 의 `ReplayVerdict.ok` 이고 `total_compared` 가 매니페스트의 evidence `EVENT_CONSUMED` 수와 같음 (b) `recovery.readiness_verdict` 가 매니페스트에 기록된 백업 시점 verdict 와 **동일**(`ReadinessVerdict` identity 비교 · `RESUME_CONSERVATIVE` 문언은 쓰지 않는다) (c) 복원 store 에 `RESTORE_DRILL_VERDICT` 기록(non-live · 결과·불일치 필드·매니페스트 digest). 셋 중 하나라도 확보 불가 = `UNKNOWN`(통과 아님). 실 라이브 데이터 디렉터리를 복원 대상으로 지정 = 거부(경로 동일성 검사).
3. **스키마 ledger 는 저장소가 스스로 검사·거부**: 런타임 소유 3 저장소(evidence · RCL · inbox)에 `SCHEMA_VERSION` 상수 + `schema_ledger(version INTEGER PRIMARY KEY, applied_at_monotonic_ns, migration_digest, applied_by)` append-only 테이블(UPDATE/DELETE 트리거 금지). 생성자: (a) **빈 파일**(테이블 0) → DDL 실행 + `user_version=SCHEMA_VERSION` + ledger `CREATED` 행(생성은 마이그레이션이 아님 · e2e 픽스처 부팅 불변) (b) `user_version == SCHEMA_VERSION` → 통과 (c) `< SCHEMA_VERSION` → `SchemaVersionRefused`(**부팅 거부 · 자동 적용 0**) (d) `>` → 거부(더 새로운 코드가 만든 파일). 마이그레이션 정의는 `operations/schema_migrations.py` 에 저장소별 `(version, description, statements)` 튜플 + statements digest — 이번 웨이브는 각 저장소 **baseline v1**(현 DDL · inbox 의 `_ADDED_COLUMNS` 컬럼 포함) 만. `migrate` CLI: 저장소 닫힘 상태 · 현 `user_version` 부터 순서 적용 · 각 단계 = 트랜잭션 + ledger 행 + `user_version` 갱신 · 기존 `user_version=0` 파일(W4 이전 생성)은 baseline 적용 시 `PRAGMA table_info` 로 현 형상 일치 검증 후 스탬프(불일치 = 거부). composite-state 는 커널 소유 → ledger 대상 아님(§6 라운드 #3 후보 · 백업 셋에는 포함).
