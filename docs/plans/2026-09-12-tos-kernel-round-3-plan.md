## 2. 결정

1. **C1 payload = 커널 레코드 + 주입 좌표, 판정은 핸들러 안 커널 술어**: `engine/records.py` `CorporateActionPayload(FrozenModel)`: `event: tos.nontrade.NonTradeEventRecord` · `envelope: TransitionEnvelope | None` · `split_spec: SplitTransformationSpec | None` · `correction: CorrectionReversalRecord | None` · `required_legs: frozenset[CredibleTransitionLegKind]` · 주입 좌표(`venue_admissibility: str | None` · `time_freshness: str | None` · `protective_action_may_proceed: bool | None` · `are_*`/`rcl_*` 좌표는 `nontrade_disposition` 16 kwarg 중 런타임이 공급 가능한 것만 필드로, 나머지는 None 고정 필드 — 필드명은 kwarg 명과 동일). `EngineEvent.corporate_action: CorporateActionPayload | None` + `_payload_matches_kind` 3엔트리. `EventKind.CORPORATE_ACTION = "CORPORATE_ACTION"` · `ADMISSIBLE_EVENT_KINDS` 3.
2. **C1 핸들러는 판정·제안만**: `EngineCore._handle_corporate_action(event, admission) -> EventResult` — (a) 커널 `nontrade` 술어들을 payload 로 호출(`transition_envelope_complete`·`favorable_netting_absent`·split 3종·`correction_reversal_idempotent`·`instrument_lineage_preserved`·`effective_window_blocks_new_risk`·`material_change_trigger_nonempty`) → `nontrade_disposition(...)` (b) `NonTradeOutcome(FrozenModel)`: `disposition` · `predicate_results: Mapping[str, bool | str | None]` · `unevaluated: tuple[str, ...]` · `capacity_remap_proposal: TransitionCause | None`(= `RECOGNIZED_EXTERNAL_CHANGE` **iff** `disposition is NONTRADE_ADMISSIBLE` 이고 payload 가 remap 대상 좌표를 가질 때 · 그 외 None) · `restrictive: bool`(비-ADMISSIBLE 4 멤버 · 어휘 `vocabulary.py:412-415` 인용) (c) `EventResult.nontrade_outcome: NonTradeOutcome | None` + `outcome_digest` 제3 분기 = `nontrade_outcome.outcome_digest`(disposition·cause·predicate_results 정렬 canonical digest) (d) **용량·투영·래치 변경 0** — `ProvisionalReservationLedger`·orthostate·halt 상태를 건드리지 않는다(구조 핀: 핸들러 본문 AST 에 ledger/projection 메서드 호출 0). 래치는 런타임 소비자(driver 가 `restrictive` 를 보고 `record_new_risk_halt` — 엔트리포인트 웨이브 · 지금은 `observe_nontrade` 문 유지).
3. **C1 replay 규칙**: `tos_runtime/engine/replay.py` — `CORPORATE_ACTION` 은 `outcome_digest` 단독 비교(EGRESS_RESULT 와 동일 등급) + `EVENT_CONSUMED` 영수증에 `nontrade_disposition` 문자열 병기(불일치 = divergence). `replay.py:407` 의 «None/None 스킵은 EGRESS_RESULT 도달 불가» 핀을 «EGRESS_RESULT·CORPORATE_ACTION 도달 불가» 로 확장. 시퀀서/플로우 지문은 DECISION_TICK 전용 그대로.
4. **C2 합성은 커널, sub-fact 는 런타임**: `egressgw/venuefacts.py`(신규 · `gateway.py` 무import · `records.py` 의 `_verdict/_positive` 공유): `venue_session_account_facts_current(session_facts_current: bool | None, tradability_facts_current: bool | None, account_facts_current: bool | None) -> bool | None` = 셋 중 하나라도 `False` ⇒ `False` · 하나라도 `None`(False 없이) ⇒ `None` · 전부 `True` ⇒ `True`(None 전파 AND · 순서 무관). `SendBoundaryContext` 에 필드 3 신설(`session_facts_current` · `tradability_facts_current` · `account_facts_current`) · **`venue_session_account_facts_current` 필드 삭제**(합성값은 게이트가 계산 · 표 밖 필드 = 구조 오류). `_check_venue_generations` 를 `venuefacts.py::venue_generation_item_verdict(context)` 로 이동(mesh 패턴): 합성값 `False` ⇒ **DENIED**(§11 결정 5) · `None` ⇒ UNKNOWN · `True` 이고 `broker_constraint_generation_current is True` ⇒ SATISFIED · broker 반쪽 `False` ⇒ DENIED · `None` ⇒ UNKNOWN. 사유 문언은 어느 sub-fact 가 막았는지 명시(첫 비양성 우선). 런타임 `compose/context.py`: `SessionFactsOwner` 가 이미 내부에서 세 sub-fact 를 계산하므로 그 셋을 노출(`session_facts_current()`·`tradability_facts_current()`·`account_facts_current()` 리더)해 필드 3 에 공급 · 합성은 더 이상 런타임이 하지 않음(`_and_with_none` 삭제) · honesty e2e 의 사유 핀은 새 문언으로.
5. **C4 release 는 finality-proof 토큰으로만**: `engine/state.py` — `PROJECTION_ORDER` 에 `RELEASED` 를 터미널 뒤 마지막 위치로 추가(주석 «cannot release» 삭제 → «releases only via finality proof») · `FinalityProofRef(FrozenModel)`: `attempt_id` · `proof_digest` · `evidence_seq` · `resolution_generation: int` · `ProvisionalReservationLedger.release(ref: FinalityProofRef) -> bool`: attempt 가 터미널 상태(FULL_FILL/CANCEL_ACK/EXPIRED/REJECT 등 기존 어휘) 이고 `ref.attempt_id` 일치일 때만 `RELEASED` 로 전이 · 응답 kind/문자열로는 불가(타입 게이트) · 이미 RELEASED 면 False(멱등) · dedup 서명 6튜플 = 기존 5 + `resolution_generation`(TIMEOUT 해소 후 같은 5튜플이 다시 오면 세대가 달라 DUPLICATE 가 아니라 새 결과 — ⓖ). 커널 테스트 3건(부재 핀) 개정 + 신규 핀. 런타임 `engine/finality_projection.py`: `FinalityReleaseConsumer.consume` 이 RCL RELEASED 를 기록한 뒤에만 `core.ledger.release(FinalityProofRef(...evidence_seq=<CAPACITY_RELEASE_INTENT seq>, resolution_generation=<witness generation>))` 호출 · 실패/False 는 evidence 로(`ENGINE_PROJECTION_RELEASE_SKIPPED`).
6. **C7 재계수**: `egressgw/__init__.py:36-41` → «정적 분할표 5 provisional(3,6,12,14,15) 은 커널 처분표 기준으로 유지 · 참조 런타임은 이제 다섯 항목 전부를 구조적으로 파생하며 **남은 운영자 attestation 0**(item 12 = `SessionFactsOwner` W5 · item 16 = `tos_runtime.safety.latch` W3)» · `gateway.py` item 12 사유 2곳 → 새 `venuefacts.py` 문언으로 대체(이동으로 자연 소멸) · `records.py:808-811` `⚠ provisional` → 필드 3 설명으로 · `test_egressgw_package.py:68-81` 를 «zero remaining» 핀으로 개정(red-first) · `docs/plans/2026-09-10-tos-phase5-recovery-governance-plan.md:31` `RESUME_CONSERVATIVE` → `ReadinessVerdict.READY`(문서) · `staterestore/__init__` 은 stale 없음(서베이 확인 · 무편집).
