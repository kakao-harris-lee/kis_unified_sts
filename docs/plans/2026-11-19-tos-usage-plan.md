## 0. 결론

TOS 는 **전략을 만드는 곳이 아니라, 전략이 실제 주문 경로에서 어떻게 움직이는지 재는 곳**이다.
쓰는 단위는 **«종목 하나 × 전략 하나 = tenant 하나»** 이고, 결과는 숫자(체결·손익·막힌 이유)로만 말한다.

1. **이번 주(11-20 ~ 11-21):** 대형주 3종목(005930 삼성전자 · 000660 SK하이닉스 · 005380 현대차)이 매일
   매수 → 매도 → 해제 → 재매수를 막힘 없이 돈다. 이틀 연속이면 «거래 경로 확정» 이다(§3).
2. **다음 2주:** 체결이 생겼으니 성과 집계(로드맵 P5)의 최소판과 종목별 운영 화면을 앞당긴다. 두 번째 전략
   (RSI / Williams %R 되돌림)을 YAML 로 올린다(§4).
3. **12월:** 리플레이(P3)로 «바꾸면 무엇이 달라지나» 를 PR 에서 본다. **2027-01:** 손절·목표(P4).
4. 판정은 §6 의 네 문장이다. 4주 MOCK 성과가 나오면 그 숫자로 «계속 · 축소 · 주식 실계좌 논의» 를 운영자가 정한다.

## 2. 주문이 왜 어려웠나 — 그래서 정한 운용 규칙

지금까지의 주식 잎 4개 합계: 송신 4 · 체결 2 대비, 정지 사유 상시 승인 1,061 · 해제 보류 855 · venue 214 ·
구성 185. 주문 자체(송신·ACK·체결)가 문제였던 적은 거의 없고, **«이전 주문이 정말 끝났나» 를 증명하지 못해
다음 주문을 막은 것**이 대부분이었다. 11-19 까지의 교착은 11-13 고아 주문 → 계좌 1주 → 해제 보류 → 체결 조회
실패(모의 API 500 · 2초 timeout) → 날짜가 넘어가 증명 이전 불가 → 청산도 진입도 거부, 의 사슬이었다.

여기서 나온 운용 규칙(코드가 이미 그렇게 강제하거나, 운영으로 지킨다):

| # | 규칙 | 이유 |
| --- | --- | --- |
| U1 | **tenant 하나는 한 번에 포지션 하나.** 동시 보유를 늘리려면 종목(tenant)을 늘린다 | 8단계 피라미딩 금지 · 해제·청산 한도·체결 증명이 모두 «범위당 진입 하나» 를 전제한다(운영자 결정 B, 11-19) |
| U2 | **한 모의 계좌에서 한 종목엔 전략 하나.** 같은 종목에 두 전략을 붙이지 않는다 | 체결 증인은 종목(PDNO)으로 조회한다. 같은 종목의 다른 tenant 주문은 서로에게 고아 주문으로 보인다 |
| U3 | **모의 계좌에 장중 수동 주문 금지** | 수동 주문은 그날 내내 고아 주문으로 남아 해제를 막는다(11-18 실측) |
| U4 | **모의 앱 키 하나당 tenant 3개까지** | 모의 API 는 초당 2건에서 거부가 시작된다. 3개 상한 1.5 req/s · 바쁠 때 약 1.33. 4번째부터는 두 번째 모의 계좌·키가 필요하다 |
| U5 | **부팅은 70초씩 엇갈린다** | 모의 토큰은 앱 키당 분당 1회 발급 → 000660 은 장 시작 70초, 005380 은 140초 늦게 시작한다 |
| U6 | **막힌 잎은 고치지 말고 보관하고 새로 시작** | 원장은 되돌리지 않는다. 계좌 평탄을 GET 으로 확인한 뒤 `archive/` 로 옮기면 다음 세션이 genesis 한다 |

지금 세 tenant 모두 **R4 프로브 규칙**(진입창 안이면 진입 → VWAP 복귀나 EOD 에 청산)으로 돈다. 이것은 전략이
아니라 «경로가 살아 있나» 를 매일 재는 카나리아다. 이틀 연속 성공이면 §4 로 넘어간다. 실패하면 실패한
단계(승인 · 구성 · venue · 해제)를 하나 고치고 같은 판정을 다시 잰다 — 새 기능은 붙이지 않는다.

## 4. 활용 모델 — 세 가지 쓰임

### 4.1 주식 전략 실험대 (주력, 11-24 ~)

종목 3개를 역할로 나눈다.

| tenant | 역할 | 전략 |
| --- | --- | --- |
| 005930 | **카나리아** — 주문 경로가 매일 살아 있는지 | R4 프로브 유지(운영자 11-18 「R4 프로브 진입 규칙은 켜둬」) |
| 000660 | 실험 A | Setup D LONG (R1 진입 · R2 VWAP 복귀 · R3 EOD) — R4 끔 |
| 005380 | 실험 B | RSI / Williams %R 되돌림 (로드맵 §7 결정 2) — 새 전략 |

전략을 하나 올리는 절차(이것이 TOS 를 «쓰는 법» 이다):

1. **지표:** 카탈로그에 있으면 `fields.yaml` 에 선언만 한다. 없으면(RSI · Williams %R) 카탈로그 지표를
   더하는 코드 PR 하나 — 참조 구현(TA-Lib) 정답 · look-ahead 금지 · 결정론 테스트. 전략 이름이 아니라
   파라미터를 받는 일반 지표로 만든다.
2. **규칙:** `strategies/*.strategy.yaml`(비교 + AND/OR) · `strategy_bindings.yaml`(임계값).
3. **세대:** 규칙이 바뀌면 결정 세대를 올리고(`decision_generations.yaml`), 그 종목 잎을 계좌 평탄 확인 뒤
   보관한다(U6). 15:40 뒤 머지.
4. **관찰:** 매일 `sts tos status`, 이상한 날은 `sts tos inspect <session>` 으로 «어느 비교식이 막았나».
5. **판정:** §6 의 숫자로만.

### 4.2 선물 신호 관측기 (유지, 비용 최소)

LONG · SHORT 미니 선물 트리는 SYNTHETIC 이다. 체결 성과는 나오지 않는다(실전 선물 주문은 영구 차단).
쓰임은 «Setup D 신호가 선물에서 언제 났나» 의 기록이다. 롤 · genesis 외에는 손대지 않는다. 선물 연구에서
좋은 아이디어가 나오면 **주식 tenant 에 대응 전략을 세워** MOCK 으로 잰다.

### 4.3 성과 증명 장치 (2027-Q1)

P4(손절·목표)가 들어가야 성과 숫자가 전략의 실제 모습이 된다. 그 전 숫자는 «진입 신호 + VWAP 복귀 / EOD
청산» 의 성과로 읽는다. 주식 실계좌는 §6 판정을 본 뒤 운영자가 따로 여는 결정이고, 이 계획의 범위가 아니다.

## 6. 판정 — 계속할지 정하는 네 문장

1. 거래 경로: 세 종목이 **이틀 연속** 왕복한다(11-21 판정). 이후 카나리아(005930)가 막힌 날은 그날 원인을 하나 고친다.
2. 선언형 약속: 두 번째 전략이 **카탈로그 PR 외 코드 diff 0** 으로 MOCK 에서 돈다(12-05 판정).
3. 성과: 실험 A · B 의 **4주 MOCK 성과**(체결 수 · 실현 손익 · 승률 · 최대 낙폭)가 `sts tos perf` 한 명령으로 나온다.
4. 비용: 운영 시간(잎 보관 · 세대 bump · 호스트 복구)이 전략 작업 시간보다 긴 달이 **두 달 연속**이면 기능 추가를
   멈추고 «안전 집행 + 관측» 용도로만 유지한다.

## 7. 하지 않는 것

- 전략별 파이썬 코드, 레지스트리 부활, DSL 을 범용 언어로 키우기(로드맵 §4).
- 한 tenant 안의 다중 포지션 · 피라미딩(U1). 필요해지면 그때 커널 설계부터(별도 계획).
- 모의 계좌 하나에 tenant 4개 이상(U4). 늘리려면 두 번째 모의 계좌를 먼저 만든다.
- 실전 선물 주문 · 증거금(비협상 규칙). 주식 실계좌는 §6 숫자를 본 뒤 별도 결정.
- 새 판정 장치. 새 검사는 그것이 막았을 실제 사고를 옆에 적는다(R5).
