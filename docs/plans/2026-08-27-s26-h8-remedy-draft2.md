## 0. 초안 1 이 무너진 자리 (26차 등재 요약)

① 파생 술어 fail-open 셋 · ② 딛는 아티팩트에 기계 소비처 없음 · ③ 검사기 사실 주장 셋 중 둘이 거짓 ·
④ 살아남는 강제 편집 둘(재결속 기입 · 심사 이력 행).  **초안 2 는 네 축을 전부 덮어야 한다.**

## 1. 피연산자 — 「심사된 내용」 (초안 1 의 blob id 를 대체)

```
REVIEW_DIGEST(commit, paths) :=
  { printf '%s\n' <commit> ;
    printf '%s\0' <paths> | LC_ALL=C sort -z -u | xargs -0 -r shasum -a 256 ; } \
  | shasum -a 256 | cut -d' ' -f1
```

`paths` 는 **산출물이 스스로 기록한 `reviewed_plan_paths`** 를 쓴다(가정하지 않는다).

**실측 (재현 명령은 §9-A)**: 레인 B 산출물 **일치 15 · 불일치 0 · 해석불가 22**.
해석불가 22 는 전부 **계약 파일이 존재하지 않던 커밋**이며 **불일치로 접힌다(fail-closed)**.

**왜 blob id 가 아닌가**: blob id 는 «파일이 무엇이었나»만 결속한다.  이 digest 는 **심사가 실제로
본 내용**을 결속하므로 20차 ⓑ 가 등재한 **편집 → 심사 → 되돌림** 창까지 닫는다.

**26차의 자기 정정 반영**: 「`plan_scope_digest` 는 HEAD 를 포함하니 못 쓴다」는 **저장값 대조**에만
맞다.  **커밋 트리 재계산**에서 commit 은 «기록된 입력»이지 무효화 인자가 아니다.

**귀결(등재)**: 실측상 `reviewed_plan_paths` 는 **두 파일**(계약 · 개발계획)이다.  따라서 ② 는
**두 파일 모두의 동결**을 요구한다.

## 2. 파생 술어 — 초안 1 의 세 fail-open 을 각각 닫는다

```
REVIEWED(현행 커밋) :=
  ∃ 스탬프 S 로서
    (a) 필수 필드 전건 성립
        reviewed_at_head        ~ ^[0-9a-f]{40}$  ∧  rev-parse --verify <sha>^{commit} 성공
        reviewed_plan_paths     비어 있지 않음
        reviewed_scope_digest   ~ ^[0-9a-f]{64}$
        adjudicator == codex    ∧  verdict ∈ {approve, needs-attention}
    (b) REVIEW_DIGEST(reviewed_at_head, reviewed_plan_paths) == reviewed_scope_digest   (자기 정합)
    (c) REVIEW_DIGEST(현행 커밋,        같은 paths)          == 그 값                    (현행 결속)
```

* **(a) 가 fail-open ⓐ 를 닫는다** — 초안 1 은 head 가 빈 문자열일 때 `git rev-parse ":<경로>"` 가
  **인덱스 blob(= 현행 blob)** 을 돌려줘 «항상 일치»가 됐다(26차 실측).  정규식이 **빈 값을 탈락**
  시키므로 그 인자 형태가 **애초에 구성되지 않는다**.
* **(a) 가 fail-open ⓑ 를 닫는다** — 「∃ verdict」가 아니라 **판정이 내려졌는지**를 본다.
  실측: 같은 계약 blob 을 가리키는 산출물 둘 중 하나가 `adjudicator: null · verdict: null`
  (쿼터 소진 fail-closed 기록)이다.
* **(b) 는 초안 1 에 없던 축**이다 — 산출물이 자기 값과 정합하지 않으면 **미관측**.

## 3. 적대 스키마 — 「미해독은 null 이 아니다」의 기계 이행

**스탬프에 필수 필드를 갖춘 산출물이 없으면 그 스탬프는 «미해독»이고, 미해독 스탬프가 하나라도
있으면 ② 의 카운트를 «진행할 수 없다»**(fail-closed).

* 근거: 적대 사이클(addendum)은 **다른 스키마**로 결속을 적는다(`계약 blob (NEW)/(BASE)` · `대상 동결`).
  그것을 «없는 것»으로 접으면 **high finding 을 낸 사이클이 보이지 않는다** — 9차가 비싸게 배운
  「**미도착 레인은 null 결과가 아니다**」가 설계 층에서 재발한다.
* **[rev.1 자기 정정 — 이 규칙을 «전 이력»에 걸면 «영원한 차단»이다]**  실측: 스탬프 **총 43** 중
  필수 필드 전건은 **23** 이고, **`verdict.md` 부재 6**(적대 산출물) · **필드 부족 14**(필드 규약
  «이전»의 과거 verdict) 이다.  **그 14 는 규약 통일로 닫을 수 없다 — 이미 지나간 산출물이다.**
  전 이력에 걸면 ② 는 **원리상 영원히 0** 이고 초안 2 도 초안 1 과 같은 자리에서 실패한다.
* **정정 — 미해독 차단을 «카운트 창»으로 스코프한다.**  ② 는 「**연속하는 두 사이클**」이므로
  **그 창에 해당하는 스탬프만** 해독을 요구한다.  **창 «안»의 적대 사이클이 미해독이면 차단**
  (§3 이 지키려던 것이 정확히 이것이다) · **창 «밖» 과거의 미해독은 이력이며 무관**하다.
  창은 스탬프 시각 순서로 정해지므로 **해독 없이도 식별된다**(순환 없음).
* **대가(정직)**: 그래도 **다음 두 사이클의 산출물이 규약을 지켜야** ② 가 진행한다 — 즉 **적대
  산출물 규약 통일이 여전히 선행**이고, **지금 시점의 ② 는 0** 이다.  그것은 **참인 상태**이며
  열린 등재는 거짓 종결보다 낫다.
* **닫는 길**: 적대 산출물에도 같은 필수 필드를 요구하는 규약.  그 산출물들은 **이미 blob 과 동결
  커밋을 적고 있으므로 필드명 통일이면 족하다** — 새 정보를 요구하지 않는다.

## 4. 무결성 — 반-위조 논증의 정정

초안 1 은 「아티팩트가 선언하면 위조 표면」을 근거로 새 아티팩트를 거부했다.  **그 논증은 자기가
고른 아티팩트에도 그대로 적용된다**(26차 부수).  정정한다:

* 옳은 근거는 「선언 vs 구조 파생」이 **아니라** **«커밋돼 있고 이력이 있다»** 이다.
* 그래서 요구한다 — 스탬프 산출물은 **커밋돼 있어야** 하고(워킹트리 전용은 미관측),
  `reviewed_at_head` 는 **그 산출물을 담은 커밋의 조상**이어야 한다(사후 날조가 이력 재작성을 요구).
* **잔여(등재)**: **커밋된 위조는 여전히 가능**하다.  저장소 신뢰 뿌리와 **같은 등급**이며 그보다
  강한 보증은 이 축의 범위 밖이다 — 그렇게 적는다.
* **부수 요구**: 이 파생은 `docs/reviews/` 를 **최초의 기계 소비처**로 승격시킨다.  실측상 지금 그
  디렉터리를 읽는 도구는 사실상 없고 **최근 스탬프 다수에 `verdict.md` 가 아예 없다** — §3 의
  규약 통일이 선행 조건인 이유다.

## 6. 검사기 — 실측된 사실 위에서만

초안 1 은 검사기 사실 주장 셋 중 **둘이 거짓**이었다.  이번엔 사본 시뮬레이션 실측을 전제로 적는다.

* **C4A(태그 N ↔ 현행 회차)는 태그가 0 이 되면 죽는다(참)** → 폐지하고 **CARD 축 신설**:
  「**이력 표 «밖» 층 태그 수 == 0**」.
* **[rev.1 자기 정정 — 「저작자 문자열로 켤 수 없다」는 «거짓»이다]**  합성 실험 실측:
  `| **v2.23** | 현행(**99차 이후**) … |` → `is_history_row = True` — **면제가 켜진다**
  (판정 = 「표 행 ∧ 첫 셀이 버전 리터럴」이므로 그런 행을 «만들면» 된다).
  **다만 provenance 면제와는 «동연»이 아니라 «정도 차이»다**: provenance 마커는 저작자가 **매 회차
  이미 타이핑하는 문자열**이라 우회가 «공짜»였지만, 버전-키 표 행은 **일부러 조작해야** 하고 그
  리터럴은 이미 S-11·S-12 의 감시 아래 있다.  **그 차이를 «불가능»으로 적은 것이 이 초안의 오류**다.
* **강화안(rev.1 신설)**: 면제를 「첫 셀 버전 리터럴이 **현행 버전 «이하»**일 때」로 좁힌다 —
  **미래 버전 리터럴로 면제를 켜는 길**이 닫힌다(현행 버전은 헤더의 «유일 소스»에서 파생된다).
* **C4B 모집단은 태그 제거 후에도 불변(실측)** → **손대지 않는다**.
* **C4C 는 태그가 사라지면 죽는다(실측 · limb 이 «태그 보유» 블록 안에 있다)** → 모집단을
  **「이력 표 밖 전 필드」** 로 재정의한다.
* **모집단 붕괴를 시끄럽게 만든다** — 실측: 뮤테이션이 전부 «행 덧붙이기»라 **태그 0 에서도 배터리가
  전건 green** 이었다.  각 축에 **「모집단이 0 이면 red」** 를 붙인다(9차 «비-vacuity» 요구의 이행).
* **④ 를 위한 모집단 신설** — 헤더 인용 블록의 심사 상태 진술.  **형상이 아니라 «블록 위치»로**
  모집단을 잡는다(a11 교훈: 의미를 정규식으로 가르려 하지 마라).

**남는 강제 편집 0** — 단, §8 의 선행 조건이 충족될 때에 한한다.

**[rev.1 — 이 표를 «O-6 절차»로 독립 추적한 결과]**  §12.3.2 가 적은 정상 순서는
「판정 수령 → 개정 → 동결 → **재결속** → 재심」이다.  **청정 사이클에는 «개정»이 없으므로**
남는 것은 **재결속**뿐이고, **재결속은 `OQ-11-DISPOSITION` 아티팩트를 편집하지 계약을 편집하지
않는다**.  20차 ⓑ 가 ⑥ 의 측정자를 **계약 «경로»로 스코프된 이력 술어**로 못박았으므로 그 편집은
카운터를 리셋하지 않는다.  보강 실측: **`bound_set_digest` 의 «값»은 계약 본문에 0회**다.
**→ 반례 못 찾음.**  (독립 반증 레인은 이 축에서 **미도착** — §10.)

## 8. 이 초안이 «닫지 못하는» 것 (등재)

1. **미해독 스탬프가 남아 있는 한 ② 는 0** — 적대 산출물 규약 통일이 **선행**이다.
2. **커밋된 위조** — 저장소 신뢰 뿌리와 같은 등급.
3. **개발계획 파일도 동결**돼야 한다(`reviewed_plan_paths` 가 둘).  이 아크가 그 파일을 편집하지
   않으므로 실무상 성립하나, **그 파일을 고치는 순간 ② 가 리셋된다**는 사실은 등재한다.
4. **③ 은 운영자 결정 대기** — 결정 없이 초안 2 는 완결되지 않는다.

## 9. 재현

### 9-A. §1 실측

```bash
# 별칭 주의: 이 환경의 mkdir 은 -pv 로 별칭돼 있어 생성 경로를 stdout 에 섞는다.
#            반드시 `command mkdir` 로 우회한다.  (이 함정에 실제로 한 번 걸렸다.)
P1=docs/plans/2026-08-12-tos-phase0-completion-contract-design.md
P2=docs/plans/2026-08-11-tos-completion-development-plan.md
for v in docs/reviews/phase0-completion-contract/*/verdict.md; do
  H=$(grep -oE '^reviewed_at_head:[[:space:]]*[0-9a-f]{40}' "$v" | grep -oE '[0-9a-f]{40}')
  D=$(grep -oE '^reviewed_scope_digest:[[:space:]]*[0-9a-f]{64}' "$v" | grep -oE '[0-9a-f]{64}')
  [ -n "$H" ] && [ -n "$D" ] || continue
  d=$(mktemp -d); command mkdir -p "$d/docs/plans"
  git show "$H:$P1" > "$d/$P1" 2>/dev/null && git show "$H:$P2" > "$d/$P2" 2>/dev/null || { rm -rf "$d"; continue; }
  R=$( cd "$d" && { printf '%s\n' "$H"; printf '%s\0' "$P1" "$P2" | LC_ALL=C sort -z -u \
       | xargs -0 -r shasum -a 256; } | shasum -a 256 | cut -d' ' -f1 )
  [ "$R" = "$D" ] && echo "MATCH $v" || echo "MISMATCH $v"
  rm -rf "$d"
done
```

### 9-B. 검사기 사실 (§6)

사본 시뮬레이션으로만 확인한다 — **저장소 파일을 고치지 않는다**.
`cp <계약> /tmp/sim.md` 후 층 태그를 치환하고 `tools/tos_contract_check.py --contract /tmp/sim.md --report`.

## 10. 이 초안의 심사 상태 (정직 기록)

* **자기 반증 둘** — §3(영원한 차단)과 §6(면제를 켤 수 있다)은 **저작자가 스스로 찾아** rev.1 에서
  정정했다.  초안 1 이 «검사기 사실 주장 셋 중 둘이 거짓»으로 무너진 뒤라, **주장을 실측 앞에
  세우는 순서**를 지켰다.
* **독립 반증 레인은 «미도착»** — 이 rev.1 발행 시점에 레인이 시뮬레이션 산출물은 남겼으나 보고를
