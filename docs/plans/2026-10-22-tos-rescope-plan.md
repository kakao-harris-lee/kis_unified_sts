## 2. 새 완료 정의 — `TOS_PAPER_READY` 하나

G1~G3 와 행 단위 Evidence 체계를 이 하나로 대체한다. 다섯 문장이 모두 참이면 끝난다.

1. **무인 운용**: CP-3 Setup D 세션(LONG, 그리고 운영자가 켜면 SHORT)이 **연속 10 거래일** 사람 손 없이 08:45~15:45
   돌고, 장후 B3 대조에서 `unresolved = 0`, 설명 안 되는 divergence 0.
2. **주문 경로 하나**: 주식 MOCK 주문이 TOS 경계(결정 → 승인 → RCL 예약 → 17-item verify → `kis_mock` 전송 →
   결과 → finality)를 **끝까지** 통과한다. 선물은 `SYNTHETIC_FUTURES_ORDER` 그대로. 실주문 0.
3. **죽어도 중복 없음**: 전송 직전·직후·결과 수신 직후 세 지점에서 `kill -9` → 재기동 drill 을 각 3회, 중복 송신 0,
   용량은 보수적으로만 복구.
4. **폴백 없음**: `MOCK → REAL` 주문 폴백과 read-only principal 의 주문 도달을 막는 테스트가 CI 필수 체크에 있다
   (원 계획 §2.2 불변식 — 이것만은 줄이지 않는다).
5. **한 장 상태판**: 운영자가 «오늘 무엇이 돌았고 무엇이 막혔나»를 한 화면/한 명령으로 본다
   (기존 `sts` CLI 또는 dashboard 의 읽기 전용 경로).

**하지 않는 것(명시적 폐기)**: 409 행 Evidence 실행 · EV-L1~L4 행별 독립 리뷰 체인 · S-26 계약 종결 · RCL 합의/쿼럼
(단일 노드 SQLite WAL 로 충분 — 단일 호스트 paper 다) · ADR 45건 `Accepted` 승격 · root 리팩터링(§7.2) 착수 ·
SBOM/배포 매니페스트 · 대형 모듈 분해 예산 레지스터.

Evidence 레지스터는 **동결된 역사 기록**으로 남긴다(지우지 않는다). `tos_spec_status.py --check` 와 `tos-gate`
는 회귀 방지용으로 계속 돈다.

## 5. 심사·검토·리뷰 — 무엇이 문제였고 어떻게 바꾸나

### 5.1 진단 (이 저장소에서 관측된 것)

1. **판정 장치가 판정 대상보다 커졌다.** 완료 «조건»을 정하는 문서가 10,723줄이 됐고, 그 문서 자체를 심사하는 데
   81회가 들었다. 계약은 결국 자기 종결 조건(S-26 ⑧)을 «현재 충족 불가»로 적었다 — 끝나지 않게 설계된 것이다.
2. **지적 → 가드 추가 → 그 가드에 대한 지적**의 순환. 리뷰가 LOW 하나를 내면 문서·검사기·대조군이 함께 늘었고,
   늘어난 표면이 다음 라운드의 지적 대상이 됐다(에라타 58차).
3. **리뷰 라운드에 상한이 없었다.** 문서 PR 하나(#909)가 4라운드, 계약은 수십 라운드. LOW 도 재리뷰를 불렀다.
4. **같은 모델이 쓰고 같은 모델이 심사**하는 구간이 길었고(Claude 레인), 그래서 «독립성»을 문서로 보강하려 했다 —
   보강 문서가 다시 심사 대상이 됐다.
5. **산출물 대비 문서 비율**: 10월 커널 커밋 0 인데 TOS 계획 문서는 122개·8.2만 줄.

### 5.2 바꾸는 규칙 (M0 에서 CLAUDE.md 에 반영 — 운영자 승인 후)

| 규칙 | 내용 |
| --- | --- |
| R1 위험 등급별 리뷰 | **A 등급**(주문 송신·자격증명·리스크 한도·데이터 파기): 독립 리뷰 1회 + Codex(운영자 승인 시). **B 등급**(그 밖의 코드): 리뷰 1회. **C 등급**(문서·측정 기록·증거 PR): 리뷰 없음 — 작성자가 출처 대조 체크리스트만 돌리고 머지. |
| R2 라운드 상한 | 리뷰는 **최대 2라운드**. 2라운드 뒤 남은 지적은 이슈로 분리하고 머지한다. LOW 는 재리뷰를 부르지 않는다 — 고치고 바로 머지. |
| R3 차단 기준 | 머지를 막는 것은 «이 입력이면 이렇게 틀린다»가 적힌 HIGH 이상뿐. 문구·인용 행 번호·표현 정밀화는 차단 사유가 아니다. |
| R4 계획 문서 상한 | 새 계획 문서는 **300줄 이하**. 넘으면 범위를 쪼갠다. 계획은 리뷰하지 않고 운영자가 읽고 승인한다(기존 지시 유지). |
| R5 가드 추가 비용 | 새 검사기·대조군·레지스터를 추가하려면 «그것이 막는 실제 사고 1건»을 적어야 한다. 가상의 공격 경로만으로는 추가하지 않는다. |
| R6 메타 금지 | «완료 조건의 완료 조건» 같은 자기 참조 판정 장치를 만들지 않는다. 완료 판정은 §2 처럼 **측정 가능한 문장 몇 개**로 쓴다. |
| R7 측정 기록 경량화 | 세션·측정 증거는 «명령 + 결과 숫자 + 로그 경로» 표 하나로 남긴다. 로그 행 번호 인용 의무를 없앤다. |

### 5.3 기대 효과와 위험

- 효과: 리뷰가 위험이 있는 곳(주문·자격증명·리스크)에만 집중된다. 문서 PR 이 하루 안에 닫힌다.
- 위험: C 등급 문서에 사실 오류가 남을 수 있다 — 오늘 #909 리뷰가 잡은 «관리자 우회 창» 같은 사실 누락이 그 예다.
  완화: 운영 판단에 쓰이는 사실(권한·보호 설정·주문 경로)이 들어간 문서는 B 등급으로 올린다. 판단은 작성자가 하되
  PR 본문에 등급과 이유를 한 줄 적는다.
