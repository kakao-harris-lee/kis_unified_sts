## 1. 무엇을 만드는가

장중에 mini KOSPI200 선물 front month(`shared/instruments/futures.py::get_front_month_code(product="mini")`,
10-12 부터 `A05611`)의 **완성된 1분봉마다 저널 한 줄**을 append 하는 호스트 프로세스. 한 줄의 모양은 B1a
(`tools/tos_cp3/produce_fields.py`)의 레코드와 같고 다른 것은 셋뿐이다:

| 키 | B1a(오프라인) | ③(실시간) |
| --- | --- | --- |
| `as_of_ms` | 봉 라벨 = OPEN (`derive_as_of_ms`) | **저널 파일을 교체하기 직전의 벽시계 시각** (§2 1) |
| `source_id` | `tos-cp3-b1a/<ver>` | `tos-cp3-live/<ver>` |
| `received_ms` | 없음 | REST 응답을 받은 벽시계 시각 |

`raw_event_id`(`derive_raw_event_id`, `{symbol}:1m:{bar_kst}`)와 열다섯 필드(`FIELD_ORDER`)는 **B1a 와 같은
함수가 만든다** — 같은 봉의 실시간 줄과 오프라인 줄이 B3(`tools/tos_cp3/diff_decisions.py`)의 `raw_event_id`
조인으로 대조된다.

## 2. 구속 요구 (머지된 결정에서 온다 — 이 계획이 바꾸지 않는다)

1. **`as_of_ms` = 기록 시각.** tenant `critical_input_policy.yaml` 의 열다섯 `max_age_ms` 가 800(커널 시간 예산
   1000 − 지연 한도 4×50, 운영자 결정 2026-10-09, #887)이라 라벨 도장은 최소 나이 60,000 ms 로 전부 STALE 이다.
   한도 상향은 배제됐다(tenant README §7.1).
2. **예산.** tenant `marketfeed.yaml` 은 최악 나이 = 수집기 지연 + `poll_interval_ms` 400 + 패스 여유 100 이라 적고
   수집기 몫을 300 ms 로 남긴다(그 파일 자신이 패스 여유 100 은 강제되지 않는다고 적는다). 생산자의 계산·네트워크
   지연은 `as_of_ms` 를 찍기 **전**이라 이 예산 밖이다 — 안에 드는 것은 「도장 → 임시 파일 쓰기 → `os.replace`」
   구간뿐이고, 그 구간을 M6 으로 잰다. 봉 마감에서 기록까지의 지연은 결정 지연으로 따로 잰다(M2).
3. **원자적 기록.** `JsonLinesObservationJournal.poll` 은 매번 파일 전체를 다시 읽고 반쯤 쓴 줄도 전체 거부한다
   (`tos/runtime/src/tos_runtime/marketfeed/journal.py` 모듈 docstring). 그러므로 매 기록은 임시 파일 +
   `os.replace` 로 파일 전체를 교체한다. 저장소 안 선례: `tools/tos_cp3/bootproof_journal.py`(#892)의 원자적 교체
   · `scripts/tos/render_paper_config.py` 의 저널 기록. (상주 세션의 `append_observation` 은 저장소 밖 호스트
   스크립트 `~/.config/kis-probes/tos_paper_session.py` 이고 같은 꼴이다.)
4. **줄당 정확히 한 번 소비 — 따라잡기 묶음 금지.** `decide_tick` 은 폴링된 묶음에서 **가장 새 관측 하나**만
   고르고(`marketfeed/scheduler.py::decide_tick`) `store.put` 이 `latest_as_of` 를 전진시키므로, 두 패스 사이에
   두 줄이 들어오면 **오래된 줄은 영원히 소비되지 않는다**(침묵). 그래서 생산자는 한 번의 기록에 **한 줄만**
   더한다. 밀렸으면(여러 봉이 한꺼번에 완성) 가장 최근 완성 봉 하나만 쓰고 건너뛴 봉은 로그에 `skipped_behind` 로
   남긴다 — 결정은 최신 봉에서만 의미가 있다.
5. **`as_of_ms` 단조 증가.** 리더는 `after_as_of_ms` 보다 큰 줄만 돌려준다. 직전 줄 이하가 되면 보정하지 않고 그
   기록을 거부하고 로그한다(시계 역행은 결함).
6. **부팅 증명 가드(#892) 허용 목록.** `bootproof_guard.APPROVED_REAL_PRODUCER_PREFIXES` 는 의도적으로 비어 있고,
   ③ 의 PR 이 접두를 더한다. 접두 `tos-cp3-live`, `source_id` = `tos-cp3-live/<ver>`(구분자 규칙).
7. **지정 data dir 첫 기록 = ③ 실데이터.** 계획 2026-10-09 §2.5 그대로.

## 3. 설계

### 3.1 재사용 — 필드 계산을 새로 쓰지 않는다

열다섯 필드는 **`produce_fields.produce_bars` 를 그대로 호출**해 얻는다. 매 분:

```
frame = 시드 봉 ++ 오늘 동결된 봉                           # B1a 와 같은 열, append-only (§3.3)
produced = produce_bars(frame, symbol, strategy, contract_spec,
                        anchor=resolve_open_anchor(...))    # 앵커는 B1a 의 해석기에서 — 하드코딩 금지
last = produced.records[-1]
```

- `last` 가 방금 완성된 봉이 아니면 기록하지 않는다. 그 경우는 둘뿐이다(리뷰 확인): `_inputs_unusable` 생략 ·
  전일 종가 없는 세션 생략. 둘 다 B1a 도 같은 봉을 생략하므로 B3 는 발산하지 않는다 — **결함이 아니라 자기 사유**
  (`omitted_unusable`)로 로그한다.
- **왜 증분 엔진이 아니라 매 분 배치 재실행인가.** `produce_bars` 는 `check()` 를 봉마다 정확히 한 번 불러 인과
  창을 전진시킨다. 같은 함수를 쓰면 필드 정의가 하나다. 증분 구현은 두 번째 구현이고 동일성 증명이 따로 든다.
  비용(M3)이 1 초를 넘으면 그때 재검토한다.
- 마지막 레코드가 인과적인 근거(리뷰 확인): ATR 은 후행 SMA14, VWAP 은 세션 시작 앵커, `_bar_lookup` 은 프레임
  조회뿐이다. `atr_90th_percentile` 은 미래를 보지만 Setup D 가 읽지 않는다. 그러므로 **프레임이 같으면** 마지막
  레코드는 오프라인과 같다 — 문제는 프레임을 같게 만드는 것이고, 그것이 §3.2–§3.3 이다.
- 기각: `CandleAccumulator` — 틱 입력용. 기각: TOS `transport/kis_quote` — MOCK 봉인·현재가 전용·방화벽상 import 불가.

### 3.2 시드 — `vol_window` 를 채울 때까지 (리뷰 H2)

- `_atr_window`(`vol_window_bars` 780)는 **진입 창 안 봉**(`valid_minutes_min` 15 ~ `no_entry_after` 345, 세션당
  331 봉)에서만 전진하고, 시드 첫 세션은 전일 종가가 없어 통째로 건너뛴다. 3 세션 시드는 오늘 09:00 에 창이 662 로
  780 에 못 미치고 `hi_vol` 의 90 분위가 B1a 의 긴 창 실행과 ~10:58 까지 다르다.
- 그래서 시드는 **세션 수가 아니라 창 충족으로** 정한다: 거래일을 거꾸로 받아 가며, 세션 2..N 의 진입 창 봉 수
  합이 `vol_window_bars`(전략 YAML 에서 읽는다) 이상이 될 때까지 늘린다(보통 4–5 세션). 기동 시 이 합을 단언하고
  미달이면 **기동 거부**.
- 거래일 선택은 **런타임이 세션 게이트에 쓰는 바로 그 달력** — tenant 트리의 `calendar.yaml` 휴장일 집합 — 에서
  한다. ⛔ `shared/collector/historical/calendar.py` 는 쓰지 않는다: 그 모듈의 하드코딩 `KOREAN_HOLIDAYS` 는 2026
  대체휴일 둘(08-17 · 10-05)이 빠져 `config/market_schedule.yaml` 과 런타임 달력에 어긋나고(v2 재리뷰 H1), 그것을 쓰면
  10-12 시드가 10-05 빈 응답에서 기동 거부로 막힌다. 동등성 테스트는 방화벽 때문에 한 테스트로 양쪽을 들 수 없으므로
  #892 의 경첩 꼴로 한다(v3 재리뷰 L1): 거래일 목록 픽스처를 커밋하고, `tos/runtime/tests` 쪽은 **실제 런타임 달력
  로더**가 그 목록을 내는지, `tests/tools` 쪽은 생산자가 같은 목록을 바이트 동일하게 재생성하는지 단언한다. 그 모듈의
  표류 자체는 별도 이슈로 연다(이 계획 범위 밖).
- 달력 범위: tenant 달력은 2026 만 담고 06-03 · 12-31 은 미확정 후보로 적혀 있다(v3 재리뷰 L2). 시드 지평이 달력이
  덮는 연도를 벗어나면 빈 응답을 기다리지 않고 **기동 전에 명시적으로 거부**한다(2027 년 1 월 초 세션이 첫 대상).
  달력 안의 휴장일 빈 응답은 결측 세션이 아니라 달력 오류로 거부한다.
- **밀도 게이트를 B1a 와 같게.** B1a 는 하루 봉 수가 게이트(기본 330) 미만인 날을 통째로 버린다. 시드에도 **같은
  상수를 같은 함수로** 적용하고 값과 버린 날을 lineage 에 남긴다. 롤 직후 얇은 날이 버려지면 위 충족 규칙이 더
  과거로 간다.

### 3.2a 월물 교차 시드 — 롤 공백 해소 (v8, 운영자 결정 2026-10-14)

§6.2 의 선택지 2 를 운영자가 골랐다(2026-10-14, 대화). §3.2 의 창 충족 규칙·밀도 게이트·런타임 달력은 그대로이고,
**시드 세션을 어느 월물에서 가져오는가**만 바꾼다. 구현은 PR-2 뒤 별도 PR(**PR-2b**, §4), 기한은 다음 롤(11-12
만기) 전이다. 10 월 롤에서는 같은 월물만으로도 10-15 부터 창이 차므로 첫 genesis 는 이 PR 을 기다리지 않는다.

- **세션별 월물 = 그날의 front month.** 시드가 거꾸로 걷는 거래일 d 마다 월물을
  `shared/instruments/futures.py::get_front_month_code(product="mini", target_date=d)` 로 정한다(오늘의 종목을 정하는
  바로 그 함수 — 두 번째 롤 규칙을 쓰지 않는다). 그 함수는 만기일 당일까지 직전 월물을 돌려주고(`target_date >
  expiry` 에서 넘어감) 10 월 롤로 보면 10-08 = `A05610`, 10-12 = `A05611` 이다. 밀도 게이트는 **(d, 그날 월물)** 쌍에
  적용한다. 시드 창 안에 접합 지점은 **최대 하나**다 — 둘 이상이면(창이 한 달을 넘는 비정상) 기동 거부.
- **접합일 = 걸음이 직전 월물에 배정한 마지막 시드 거래일.** `get_expiry_date(...)` 로 다시 계산하지 않는다 — 그
  함수는 휴장일 보정이 없어 둘째 목요일이 휴장인 달에는 공통 분이 0 이 된다(리뷰 LOW-1). 걸음이 고른 날이 곧 접합일이다.
- **가격 정렬 = 차분 백어저스트(Panama).** 직전 월물 구간의 OHLC 전부에 상수 `c = P_new − P_old` 를 더한다.
  `P_new`·`P_old` 는 접합일에 두 월물 모두 **파싱된(저장되는) 봉**이 있는 **마지막 같은 분**의 종가다 — 원시 행이 아니라
  `parse_ohlcv`(거래량 하한 §3.3 핀) 뒤의 봉이다. 생산자와 오프라인이 같은 저장 봉에서 `c` 를 얻게 하려는 것이고, 만기
  직전의 얇은 분(거래량 < 하한)이 한쪽에만 남아 두 쪽이 서로 다른 분을 고르는 일을 막는다(재리뷰 N-3). 공통 분이 없으면 기동
  거부(값을 지어내지 않는다). 거래량은 바꾸지 않는다. `c` 는 **정수 `c_x100`** 으로 정하고 저장한다 — 부동소수
  차는 격자 위에 정확히 떨어지지 않는다(리뷰 LOW-2). 두 종가가 0.02 격자이므로 `c_x100` 은 정수이고 2 의 배수다.
  ⚠ **접합일의 두 월물은 세션 끝이 다를 수 있다**: 만기 월물은 만기일에 정규 세션보다 일찍 거래를 끝내는 것으로 알려져
  있으나(레포 달력 테스트는 그날도 08:45–15:45 로 둔다) 레포에 실측이 없다. 그러므로 「마지막 공통 분」은 만기 월물의
  마지막 원시 행 시각 이하이고, 그 시각의 `P_old` 는 최종결제가로 수렴 중인 값이다. 접합 직후 세션의 `prev_close`
  는 그 공통 분의 정렬 종가이지 새 월물 자신의 접합일 마지막 종가가 아니다. 전제 실측(아래)이 그 마지막 원시 행
  시각을 기록한다.
- **정렬이 무엇을 지우는가, 무엇을 남기는가.** Setup D 가 시드에서 물려받는 상태는 전부 가격 **차이**·차이의 비·세션
  리셋 값이다: ATR(SMA14 of true range), `_atr_window` 백분위(`hi_vol`), `_close_window` 의 max/min(정체 가드)과
  `prev_close`(반전 확인), `vwap_extension_z`, 세션 리셋 VWAP 추세 점수(`shared/decision/setups/vwap_reversion.py` 의
  `_vol_reference`·`_self_range`·`_trend_score`·`vwap_extension_z`). 모두 상수 평행이동에 불변이므로(리뷰가 절대가격
  의존은 `<= 0` 류 방어뿐임을 확인) **정렬은 접합 점프를 지운다**. 정렬하지 않으면 그 점프가 판별에 닿는 경로는 사실상
  `_close_window`(정체 가드의 recent high/low)와 `prev_close`(반전 확인) 둘이고, 진입 창 첫 `range_window_bars` 봉에서
  만 나타난다 — 접합 true range 는 08:45 봉에 있어 진입 창(09:00~) ATR 의 SMA14 창에 보통 들어가지 않는다.
  **남는 것 — 두 경로, 깊이가 다르다**(재리뷰 3 라운드). 생산자–B1a–B2–B3 파리티는 이것과 무관하게 유지된다(모두 같은 접합
  프레임을 본다). 리플레이는 전일 종가 없는 첫 세션의 봉을 `check()` 에 넘기지 않으므로 직전 월물 봉이 판별 상태에 들어가는
  것은 직전 월물 세션이 시드의 **두 번째 이후** 세션일 때뿐이고, 그때 경로는 둘이다:
  - **(a) 접합을 가로지르는 가격 차이** — `_close_window`(정체 가드)·`prev_close`(반전 확인). `c` 의 오차(스프레드 변동)만
    여기에 들어가고, 닿는 곳은 **접합 뒤 첫 세션의 진입 창 첫 `range_window_bars` 봉**(`prev_close` 는 그 첫 봉)뿐이다.
  - **(b) ATR 대체** — 직전 월물 세션들의 ATR 이 `_atr_window` 를 채워 `hi_vol` 의 백분위 기준을 정한다. 각 ATR 은 한 월물
    안의 차이라 `c` 와 무관하고, 「직전 월물이 새 월물처럼 움직였을 것」이라는 잔여의 본체가 이것이다. 닿는 곳은 롤 뒤 게이트
    통과 세션만으로 세션 2..N 이 `vol_window_bars` 를 채울 때까지다 — **최소 3 거래일**(780 / 331 올림)이고, 롤 뒤 날 하나가
    밀도 게이트에 걸리거나(자료 결손·반일장·개장 지연) 게이트는 통과해도 진입 창 봉이 331 개 미만이면(게이트는 하루 전체 봉을
    세므로 거래량 하한으로 빠진 분이 진입 창에 있으면) 4 일 이상으로 늘어난다. 마지막 날에는 진입 창 앞쪽 봉에서만 닿는다.
  두 잔여는 측정 S1a·S1b(아래)로 잰다. 롤 직후 날들에는 같은 월물만의 대조 프레임이 없다는 것이 이 잔여를 대조가 아니라
  민감도·대체 비교로 재는 이유다.
- **라벨은 진실하게.** 생산자는 시드 일자를 **원 월물의 파티션**(`code=<그날 월물>`)에 **미조정 파싱 봉**으로 쓰고,
  **접합일의 새 월물 미조정 파싱 봉도** 새 월물 파티션에 쓴다(`c` 재계산 근거). 레거시 A05611 Parquet 의 날짜 라벨 오류(§6.1)가
  보여 주듯, 다른 실체의 값을 남의 이름 아래 두는 순간 대조가 조용히 틀어진다. 조정은 저장이 아니라 **읽을 때** 적용한다.
- **`stitch.json` 은 항상 쓴다.** 생산자는 **`<세션 dir>/market/stitch.json`** — §3.6 이 B1a 에 넘기는 `--data-root` 바로 그 dir —
  에 접합이 없는 날도(접합 0 개) 쓴다. 내용: 대상 종목 ·
  구간별 (월물, 거래일 목록) · 방법 `difference` · `c_x100` · 접합일 · 공통 분 · 두 종가 · 원천 응답 sha256.
  `load_window(stitch_manifest=)` 는 날짜 범위 glob 이 아니라 **구간에 적힌 (월물, 거래일) 쌍만** 읽는다. 접합일의 새 월물
  파티션은 `c_x100` 재계산에만 읽고 프레임에는 넣지 않으며 lineage 에 따로 적는다 — 넣으면 같은 날 두 월물 봉이 한 프레임에
  들어가 `_bar_lookup` 의 중복 시각 거부에 걸린다.
- **오프라인 파리티 — B1a 와 B2 가 같은 함수로.** B3(`tools/tos_cp3/diff_decisions.py`)는 B1a 와 B2 의 입력 파일 다이제스트·
  줄 수·`raw_event_id` 순서가 같지 않으면 쌍을 거부한다. B2(`tools/tos_cp3/emit_legacy_decisions.py`)는
  `produce_fields.load_window` 로 프레임을 읽는다. 그러므로 정렬은 B1a 플래그가 아니라 **`produce_fields.load_window` 의
  선택 인자 `stitch_manifest`** 로 넣는다 — B1a 와 B2 가 그것을 물려받고, 생산자도 같은 정렬 함수를 부른다(두 번째 구현
  금지; 셋 다 `tools/` 안이라 방화벽과 무관). CLI 는 B1a·B2 둘 다 `--stitch-manifest`. 매니페스트 sha256 을 B3 가 실제로 비교하는 창 정체성에 넣는다: `diff_decisions.py` 의
  `WINDOW_IDENTITY_FIELDS`·`B1A_IDENTITY_PROJECTION` 에 `stitch_manifest_sha256` 을 더하고(B2 `join.window_identity` 와 B1a
  lineage 양쪽, **null = 매니페스트 없음(레거시 data root)** — `stitch.json` 은 접합 0 개인 날도 쓰이므로 생산자 세션은 늘
  non-null 이다. 키가 **없는** 이전 lineage 는 null 로 읽어 비교에 넣는다 — 부재를 비교에서 빼면 접합 B1a 와 이전 B2 쌍이 이
  검사를 그냥 통과한다. B1a 쪽 `_dig` 는 경로 부재에 예외를 내므로 같은 관용을 둔다), B2 블록에만 키를 더하면 B3 가 그 키를
  읽지 않으므로 아무것도 지키지 않는다(재리뷰 N-1). B1a·B2 는 **대상 종목이 아닌 구간의 레코드를 출력하지 않는다**(그
  봉에 대상 종목 이름의 `raw_event_id` 를 붙이면 그것이 곧 라벨 오류다 — 생략 수는 lineage 에 센다). 매니페스트를 받으면

### 3.3 데이터 원천과 봉 동결 — `FHKIF03020200` 실전 GET

- 엔드포인트 `/uapi/domestic-futureoption/v1/quotations/inquire-time-fuopchartprice`. 요청·뒤로 가는 페이지네이션
  (`FID_INPUT_HOUR_1`)은 `shared/collector/historical/backfill.py::fetch_minute_async` 의 날짜 지정 형태를 재사용한다.
  이 함수는 원시 `output2` 만 돌려주고 파싱은 `shared/collector/historical/ohlcv_parser.py::parse_ohlcv` 다. 첫 페이지에
  페이지 단위 재시도가 없다는 점은 PR-2 에서 감싼다. `client.py::_get_futures_minute_bars` 는 다른 형태
  (`PW_DATA_INCU_YN=N`, 날짜 없음)라 쓰지 않는다.
- **고정 파라미터를 핀하고 lineage 에 남긴다**(리뷰 L9): `FID_HOUR_CLS_CODE`(env `KIS_FUTURES_HOUR_CLS_CODE`, 기본
  60) · `KIS_MINUTE_BAR_MIN_VOLUME`(기본 10). 생산자는 env 값이 핀과 다르면 기동을 거부한다 — 봉 크기·생략 규칙이
  환경에 따라 조용히 바뀌지 않게. 기존 Parquet 이 같은 두 값(기본값)으로 만들어졌다는 것은 **가정**이다 — 빌드 시점
  env 는 어디에도 기록돼 있지 않고 오래된 파티션은 파서 변경(#516) 이전이다. M4 가 그 가정을 시험한다. 오프라인
  대조(§3.6)는 동결 프레임을 쓰므로 이 가정에 기대지 않는다.
- **완성 판정은 원시 행으로**(리뷰 M5): 봉 m 은 **원시 응답**에 m+1 시각 행이 있을 때 완성이다. 파싱 뒤 행으로
  보면 거래량 < 10 으로 버려진 m+1 때문에 m 이 영원히 미완성이 된다. 경계 + G 초까지 m+1 원시 행이 없으면 m 은
  `missing_no_successor` 로 로그하고 건너뛴다(무거래 봉을 합성하지 않는다).
- **동결**: `parse_ohlcv` 의 `_resolve_minute_bars` 는 응답 전체에서 앵커를 골라 행을 고르므로, 자라는 하루를 매 분
  다시 파싱하면 이전 봉이 바뀔 수 있다. 그래서 한 번 완성된 봉은 **동결**하고 다시 파싱하지 않는다. 매 조회에서는
  마지막 동결 봉보다 새 행만 파싱해 덧붙인다. 동결 프레임이 곧 §3.1 의 `frame` 이다.
  ⚠ **대가(v2 재리뷰 L2)**: 한두 행 묶음에서는 `_resolve_minute_bars` 의 앵커가 그 행들 자신에서 골라지므로 외톨이
  허상 행이 스스로를 지지해 남는다 — 파리티는 유지되지만(오프라인도 같은 동결 프레임) 데이터 품질 필터가 약해진다.
  PR-1 M4 와 PR-2 테스트가 과거 날짜에서 **증분 파싱 == 전일(全日) 파싱**을 비교해 그 차이를 잰다. 차이가 나오면
  증분 파싱에 직전 동결 봉 K 개를 문맥으로 함께 넘기는 쪽으로 고친다.
- **장 마감**: 15:35–15:45 단일가 구간은 원시 행이 없어 m+1 규칙으로 마지막 봉(15:34)이 완성되지 않을 수 있다.
  M2b 로 실측하고, 행이 없으면 「세션 종료 시각 경과」를 마지막 봉의 완성 조건으로 한다. 그 뒤 생산자는 기록을 멈춘다.

  `probes_real_order` 가 없음을 고정한다.
- 호출량: 장중 ≈ 1–3 콜/분, 시드 ≈ 수십 콜(5 rps 한도 안).

### 3.4 자격증명 분리 (리뷰 M4)

- PR-C 러너는 `TENANT_ENV_FILE` 이 `.env.mock` 이어야 한다(`run_tenant_session.sh` 가드). 런타임은 그대로 둔다.
- 생산자 **하위 프로세스에만** `.env.real` 의 선물 조회 키 두 개(`KIS_FUTURES_APP_KEY/SECRET`)를 넘긴다. 러너
  환경과 런타임 환경에는 실전 키가 들어가지 않는다. PR-3 테스트가 런타임 프로세스 환경에 그 키가 없음을 확인한다.
- 토큰 캐시: 기존 `KISToken` 캐시(`~/.cache/kis_token_futures.json`)는 도메인만으로 키를 잡고 앱 키를 보지 않는다.
  생산자는 **자기 캐시 경로**를 쓰고, 캐시 토큰을 쓰기 전에 앱 키 지문(커밋된 `secret_fingerprint`)이 일치하는지
  확인한다. `rt_cd≠0` 의 토큰 오류는 1 회 재발급 후 재시도하고, 그래도 실패하면 그 분을 `fetch_error` 로 남긴다.

### 3.5 프로세스·수명·부팅 순서 (리뷰 H1)

- 위치: `tools/tos_cp3/live_producer/`(방화벽 바깥 — `shared.*` 가능, `tos*` 불가). 크기 예산 범위에 넣는다.
- 순수 함수 `build_line(frame, now_ms, received_ms, prev_as_of_ms)` 와 얇은 바깥 루프(HTTP·파일 교체)로 나눈다.
- **부팅 순서**: #892 가드는 빈 저널을 거부한다(`bootproof_guard` 의 「holds no rows」 · `require_journal_instrument`).
  가드의 의미는 바꾸지 않는다. 러너는 ① 생산자 기동(시드) → ② **첫 실제 `tos-cp3-live/…` 줄**이 생길 때까지 대기
  (상한 있음, 넘으면 ABORT) → ③ 가드 → 렌더 → 부팅 순서로 간다. 첫 줄은 부팅이 끝날 때 이미 STALE 이므로
  `consumed_stale_at_boot` 로 따로 센다.
- 정지: 러너의 trap/`timeout` 감독 아래 런타임과 함께 멈춘다. ⛔ 지금 #892 러너는 trap 을 렌더 **뒤에** 건다 — 생산자를
  먼저 띄우면 가드·렌더·환경 라벨 거부 같은 `die` 가 생산자를 고아로 남겨 하루 종일 실전 REST 를 부르게 된다(v2
  재리뷰 M1). PR-3 은 생산자 기동 **전에** EXIT/die 정리(생산자 정지)를 건다. #892 재리뷰 LOW L1(`RUN_PID`
  초기화) · L2(`kill -KILL` 을 프로세스 그룹으로)도 같은 PR 에서. 러너 자신이 SIGKILL 되면 EXIT trap 도 돌지 않으므로
  생산자도 런타임처럼 `timeout` 상한(정지창 + 유예) 아래 띄운다. 같은 저널에 생산자가 둘이면 `flock` 으로 거부한다.
- 롤: instrument 는 인자로만 받는다. 러너가 상주와 같은 규칙으로 한 번 계산해 렌더·data dir·생산자에 같은 값을 준다.
- 개장 지연일(수능 등): 기계적 거부를 **약속하지 않는다**. `resolve_open_anchor("auto")` 는 정적
  `market_schedule.futures.regular.open` 을 돌려주고 날짜별 예외가 없어(`special_days` 비어 있음) 그 비교는 항상
  통과한다 — 아무것도 막지 않는 가드다(v2 재리뷰 M3). 대신 런북 §7.2 에 운영자 단계로 「개장 지연일에는 tenant 세션을
  돌리지 않는다」를 적는다. 날짜 목록이 config 에 생기면 그때 그 목록을 읽는 거부 + 구체 날짜 레드 테스트를 단다.
- `ProduceFieldsError`(비유한 값·중복 시각) 는 그 분을 `produce_error` 로 건너뛰고 기록하지 않는다. 연속 5 회면
  생산자를 멈춘다. 멈춘 생산자는 러너가 ABORT 로 보고한다.
  ⚠ **「멈췄다」는 「정지 시각 전에 사라졌다」가 아니다**(2026-10-15 수정 — 첫 genesis 세션이 드러냈다).
  생산자는 마지막 봉을 발행한 뒤 `end_boundary` 를 지나 **설계대로** 끝나고 그 시점은 늘 러너의 정지
  시각보다 앞이므로, 「사라졌는가」만 묻는 러너는 온전히 하루를 돈 세션을 전부 ABORT 로 보고했다. 러너는
  종료코드 0 · `stage: finish` 요약의 존재 · 그 요약의 `session_end_reached` 참을 **같이** 보고, 셋이 다
  참일 때만 「끝냈다」로 읽는다(각 절마다 다른 절이 통과시키는 구체 입력이 있다).

### 3.6 오프라인 대조 입력 (리뷰 H3)

B1a 는 `--data-root` 아래 Parquet 저장소 배치만 읽는다(`produce_fields.py` 의 `ParquetMarketDataStore`). 레거시
수집은 10-08 에 멈췄다. 그래서 생산자는 같은 저장소 배치(`<세션 dir>/market/futures/minute/code=<종목>/…`)에
**append-only** 로 쓴다(v3 재리뷰 M1):

- 시드 일자들은 기동 시 하루씩 한 번 쓴다.
- 오늘은 **봉이 동결될 때마다 그 봉 하나를 자기 part 파일**로 쓴다. 저장소의 `append_minute_bars` 는 최종 이름
  `part-<uuid>.parquet` 에 바로 `to_parquet` 하므로 원자적이지 **않다** — PR-2 가 감싼다: `.part-<uuid>.tmp` 로 쓰고
  `os.replace` 로 `part-<uuid>.parquet`. 임시 이름은 `*.parquet` 가 아니어야 한다 — B1a `discover_input_files` 의 glob 과
  저장소 `_files` 의 `rglob("*.parquet")` 가 크래시로 남은 반쪽 파일을 읽지 않게(v4 재리뷰 L1).
- **재시작은 세션 dir 을 재사용하지 않는다**(v4 재리뷰 L2): append-only 라 같은 dir 로 재기동하면 시드와 동결 봉이 중복
  기록되고 B1a 의 중복 시각 거부로 그 세션 입력 전체를 잃는다. 생산자는 세션 dir 에 기존 파티션이 있으면 기동을
  거부하고, 생산자 ABORT 는 그 세션의 끝이다(러너가 새 세션 dir 로 다시 시작하는 것은 운영자 결정).
- ⛔ `replace_minute_day` 는 쓰지 않는다: 그 경로는 일자 파티션을 `rmtree` 한 뒤 비원자적으로 다시 쓰므로 매 분
  삭제 창이 생기고, 그 창의 크래시가 바로 이 절이 막으려는 입력 소실이다. 이중 기록은 B1a `_bar_lookup` 의 중복
  시각 검사가 시끄럽게 거부한다.
- 세션 끝에만 쓰면 생산자가 연속 오류로 멈추거나 SIGKILL 될 때 진단이 가장 필요한 세션의 입력이 사라진다(v2 재리뷰
  M2). 세션 종료 시 sha256 을 남긴다.

**대조가 실제로 무엇을 보는가(v3 재리뷰 M2).** 지금 B3(`diff_decisions.py`)의 입력은 `--fields`(B1a) · `--legacy`(B2)
· `--tos`(B1b 오프라인 트레이스)뿐이고 실시간 런타임 입력도 id 필터도 없다. 이 입력으로 B3 를 돌리면 「오프라인 B1a →
B1b 가 B2 와 같다」만 확인하고, 실시간 런타임이 오프라인처럼 행동했는지는 보지 않는다. 그래서 PR-3 이 두 가지를 더한다:

1. **소비된 id 집합**: 세션 `marketfeed.sqlite3` 의 `preimages(snapshot_id, raw_event_id)`
   (`tos_runtime/marketfeed/store.py`)를 읽는 추출기(sqlite 읽기만 — `tos*` import 없음) + `diff_decisions` 의 id 필터 플래그.
2. **실시간 결정 입력**: 세션 evidence store 에서 결정 레코드를 뽑아 B1b 오프라인 트레이스와 같은 모양으로 내놓는 추출기 +
   `diff_decisions` 의 그 입력 하나. 모양 정의는 PR-3 에서 B1b 트레이스 스키마를 읽고 정한다. 장후 B1a 를 `--data-root <세션 dir>/market`
으로 돌리면 같은 프레임에서 오프라인 레코드가 나온다. 밀도 게이트는 시드와 같은 값을 쓰고, 오늘(정규 세션 ~420 봉)은
게이트를 통과한다. 미달이면 B3 대조 대상에서 그날이 빠졌다고 기록한다.

실측: A05611 의 롤 전 세션 중 밀도 게이트(330 봉)를 통과한 날은 **직전 월물 만기일(10-08) 하루

세션 세 개 × 331 봉 = 993) 대상일 앞에 있어야 한다.

그래서 **같은 월물만 쓰는 현재 규칙(§3.2)에서는 롤 직후 약 N = 3 거래일 동안 생산자가 기동할 수
없다.** 10 월 롤 실측으로는 10-12 · 10-13 · 10-14 가 막히고 최단 충족일이 **10-15** 다.
**mini 는 월물이므로(달력 `futures_expiry.months` = 1..12) 이 창은 매달 돌아온다.**
⚠ N = 3 은 롤 하나에서 나온 추정이고, 직전 월물 만기일이 밀집하지 않은 달에는 더 커진다.

선택지 — **이 계획은 정하지 않는다. 다음 롤(11-12 만기) 전에 운영자가 결정한다**:

1. **블랙아웃 수용.** 롤 직후 N 거래일은 tenant 세션을 돌리지 않는다. 가장 단순하고 §3.2 를
   바꾸지 않지만, 매달 N 일을 잃고 그 사이 genesis·대조를 할 수 없다.
2. **월물 교차 시드 접합(cross-contract stitching).** 시드의 과거 세션을 직전 월물
   (`A05610` 등)에서 가져와 잇는다. **B1a 파리티는 유지된다** — §3.6 대로 B1a 는 생산자가 쓴
   **동결 프레임**을 읽으므로, 오프라인과 실시간이 **같은 접합 프레임**을 보면 B3 는 발산하지
   않는다. 대가는 접합 지점의 가격 점프(월물 스프레드)가 ATR·VWAP·`hi_vol` 에 들어가는 것이고,
   그것이 Setup D 의 판별을 바꾸는지는 **미측정**이다. 결정 전에 백테스트로 재야 한다.
3. **기타** — 밀도 게이트를 롤 직후에만 낮추거나, `vol_window_bars` 를 줄이거나, 시드를 영구
   저장해 월물 간에 물려주는 방식. 전부 Setup D 의 판별값을 건드리므로 리튠이고, 2026-09-09
   기준 「거래값은 이 PR 에서 바꾸지 않는다」 규율에 걸린다.

⚠ 1 번을 고르더라도 **그 사실을 런북에 적어야 한다** — 적지 않으면 롤 직후 기동 거부가 결함으로
오진된다(기동 거부는 §3.2 가 의도한 거동이다).
