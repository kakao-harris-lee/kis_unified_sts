## 2. 결정

1. **캘린더는 데이터, 판정은 커널**: `tos_runtime/calendar/config.py` `load_calendar_config(path) -> CalendarConfig`(stdlib+pyyaml · named-TBD null → `CalendarConfigError` 부팅 거부 · `tz_id` 는 `zoneinfo.ZoneInfo(tz_id)` 해석 실패 = 거부(§6 ③ tzdata 이식성) · `calendar_version: str` 필수 · `holidays: [YYYY-MM-DD]`(빈 리스트는 명시 `[]`) · `sessions: {instrument_class: [{phase: str, start: "HH:MM", end: "HH:MM", days: [MON..SUN], crosses_midnight: bool}]}` · `futures_expiry: {instrument_class, weekday, ordinal, months: [..], expired_phase: str}`). 위상 토큰은 설정이 정의(커널 enum 없음 · `venue_policy.admitting_phase_rules` 와 같은 어휘) — 런타임은 문자열을 비교·판정하지 않고 **커널 `session_phase_admits` 에 넘기기만** 한다. `calendar/phase.py` 순수 함수: `session_phase_at(instant_unix_ms, instrument_class, cal) -> PhaseFact{phase: str | None, is_open: bool | None, boundary_unix_ms: int | None, source: "calendar", calendar_version}` — 휴장일·요일 밖 = 설정의 `closed_phase`(예: `CLOSED`) · 창 안 = 그 창의 phase · 창 밖 = `closed_phase` · 자정 넘김 창 지원 · **KST 는 DST 없음**을 전제하되 코드로 가정하지 않고 `ZoneInfo` 로 변환. `maturity_at(instant, instrument_class, cal) -> MaturityFact{expiry_date, expired: bool | None}`(규칙 미설정 클래스 = None).
2. **벽시계는 포트 · 프로덕션 기본은 부재(G-1 존중)**: `calendar/ports.py` `WallClockReference` Protocol `read() -> WallClockReading | None`(`unix_ms`, `source_label`). 구현: `AbsentWallClockReference`(항상 None · 컴포즈 기본 · 부팅 시 `SESSION_FACTS_SOURCE_ABSENT` evidence 1회 · 사유 «G-1 미결») · `FixedWallClockReference`(테스트 전용 · 주입 순간) · `LocalWallClockReference` 는 **작성하되 컴포즈에서 결선하지 않는다**(CLI 플래그 0 · G-1 승인 후 1행 결선 · §6 ①). 어떤 경로도 `time.time()` 값을 `TrustworthyTimeService` 스냅샷에 넣지 않는다(슬라이스 #1 결정 불변).
3. **`SessionFactsOwner`**(`calendar/owner.py`): 생성자 = 캘린더 · wall-clock 포트 · instrument-class 해석기 · evidence 기록기 · 틱 세대 리더(inbox `count` · W3.1 스냅샷 관용구). `observe(instrument_class) -> SessionFacts{phase_fact, maturity_fact, session_context: tos.time.SessionContext | None, wall_clock: WallClockReading | None}` 틱당 1회 캐시. 공급: (a) step 3 `observed_session_phase` ← `phase_fact.phase`(None 이면 커널이 UNKNOWN) (b) `SessionContext(tz_id, tz_db_version=<time.yaml>, trading_calendar_version=<calendar_version>, phase, is_open, tz_version_conflict=<time.yaml tz_db_version 대 zoneinfo 실측 불일치>, boundary_value=boundary)` → `session_open_positively(ctx, uncertainty)` 결과를 evidence 에 기록(비권위 · 판정 소비 0) (c) `venue_session_account_facts_current` 합성 = `session_current ∧ tradability_current ∧ account_facts_current` 의 **삼중 AND with None 전파**: `session_current` = phase_fact 존재 ∧ 같은 틱 세대 ∧ `calendar_version == time.yaml.trading_calendar_version`(불일치 = 부팅 거부) · `tradability_current`/`account_facts_current` = 비브로커 스코프(`endpoint_class ∈ {NONE, SYNTHETIC}`) ⇒ **구조적 True**(Phase 4 `derive_item6_item12` 와 같은 관용구 · 합성 transport 는 자기 원장이 유일한 장이라 별도 사실 없음 — §6 ④ 확인) · 브로커 스코프 ⇒ **None**(계좌/증거금·거래정지 원천 없음 · KIS 조회 TR 소비자 = transport 후속). 결과: 합성 e2e 는 순간 주입 시 True · kis-mock honesty e2e 는 None(UNKNOWN · 이미 P0-2 로 UNKNOWN 이던 것과 동일 결과 · **두 사유를 evidence 로 구분 기록**). 부팅 시 `calendar_version`·휴장일 수·세션 창 digest 를 `SESSION_CALENDAR_BOUND` evidence 1회.
