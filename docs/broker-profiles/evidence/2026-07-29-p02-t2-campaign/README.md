- TR `VTTC0081R`(주식일별주문체결조회 [v1_국내주식-005], 모의) 조회:
  ODNO `0000018925` · `ord_dvsn_name=시장가` · `ord_qty=1` · **`tot_ccld_qty=1`** ·
  `rmn_qty=0` · `cncl_yn=N` · **체결가 248,500** · `ord_tmd=105710`(10:57:10)
- 계좌 대조: `dnca_tot_amt` 10,000,000 → `prvs_rcdl_excc_amt` **9,751,470**
  (= 10,000,000 − 248,530, 체결금액+제비용). 보유 `005930` 1주의 매입평균
  **248,500**이 곧 이 체결이다 — 초판이 "P-11 이전부터의 잔량"이라 적은 것도 틀렸다.

**근본원인 = 하네스 결함 #5 (측정 논리)**: `probe_p11`이 holdings baseline을 **주문
전송 *후*에** 읽는다(전송 → `sent` 스탬프 → `baseline = client.stock_balance()`).
시장가는 밀리초 단위로 체결되므로 baseline이 **이미 자기 체결을 포함**하고,
`qty > base_qty`는 어떤 창 길이로도 참이 되지 않는다. 어제의 "창을 늘려도 안 된다"는
관측은 옳았으나 그 해석("미체결")이 틀렸다 — 창이 아니라 **기준선이 오염**돼 있었다.

**어제(07-30) 판정은 이제 검증 불가**다. 계좌 초기화가 주문 이력을 소거해
`VTTC0081R`이 `20260730`·`20260729` 모두 **0행**을 돌려준다. 어제 결론도 같은
오염된 기준선 위에 있었으므로 **"미체결 확정"이 아니라 "미확인"으로 격하**한다.

**이 세션 질문 "체결 확보 방법"의 답**: 체결 확보는 **필요하지 않다** — 시장가는
즉시 체결된다. 필요한 것은 ① baseline을 전송 **전**에 읽는 것, ② 체결 사실을
잔고가 아닌 **체결조회로 독립 확인**하는 것이다(오늘 그 조회가 판정을 내렸다).

**새 정직한 한계**: 잔고는 체결을 사실상 즉시 반영하는 것으로 보인다. 폴 간격이
`--pace-s`(1.1s)로 하한이 잡히므로 P-11은 반영 지연을 **"≤ 1 폴 간격"의 상한으로만**
말할 수 있고 점추정을 낼 수 없다. 1100ms를 측정된 지연으로 기록하면 §8.3의 가산
오차를 값으로 바꿔치기하는 것이 된다 — `submit_to_balance_ms`는 **null 유지**.

### 페이지 크기 실측 설계 — 모의 주식, 월요일(08-03) 실행안

- **목표**: 모의 주식 잔고 페이지 크기 실측(documentary 20행/호출) →
  `TRUNCATION_RISK_DEMONSTRATED`로 D-D의 절단 인과를 모의 환경에서 실증.
- **방법 — 신규 코드 0**: 인가된 기존 기제인 P-11(모의 주식 시장가 1주 매수)을
  **서로 다른 종목 24개**로 반복해 보유를 25행까지 축적(현 1행 005930 포함) →
  `P-BAL --asset stock --env mock` 재실행. 종목은 스크리너 유니버스의 저가·유동
  KOSPI 24개. 페이싱은 P-11이 자체 강제(1.1s), 24회 ≈ 1시간 내, 자금은 모의
  5억이라 무시 가능. 실행 창 09:00–15:30 KST — P-R5(선물·실전)와 자산·도메인이
  달라 병행 가능(토큰 캐시 분리 선행 조건 해소됨).
- **정직성 레일**: 25행에서도 연속조회 없이 end-of-set이면 "페이지 크기 >25"
  하한만 남는다. MOCK 실측은 REAL에 상속 금지(§13.14). REAL 페이지(documentary
  50)는 실전 주식 주문 없이 실측 불가이고 **그런 주문을 인가한 프로브는 없다**
  (P-R5는 선물 전용).
- **핵심 판단**: `client.py` 연속조회 walk 수정은 페이지 크기 값에 **무관하게**
  옳다 — 올바른 walk는 크기를 몰라도 끝까지 걷는다. 따라서 REAL 페이지 실측은
  수정의 전제가 아니며, 모의 DEMONSTRATED + documentary + D-F 실측만으로 수정
  정당화에 충분하다. REAL 실측은 수정 후 검증 단계에서 운영자 실계좌의 자연
  보유로 기회주의적으로만 수행한다.
