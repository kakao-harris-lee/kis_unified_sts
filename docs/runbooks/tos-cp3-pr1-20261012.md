# CP-3 PR-1 — 2026-10-12 조회 측정

승인: 운영자 2026-10-11 지시(#893 머지·10-12 장중 PR-1 측정).
계획: `docs/plans/2026-10-10-tos-cp3-live-field-producer-plan.md` §4 PR-1.

도구: `tools/tos_cp3/minute_probe.py`, 설정: `config/tos_probes/cp3-pr1-20261012.yaml`.
원천 파라미터는 [KIS 공식 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_futureoption/inquire_time_fuopchartprice/inquire_time_fuopchartprice.py)와
기존 `shared/collector/historical/backfill.py::fetch_minute_async`를 대조했다.
기존 backfill 함수는 전역 토큰 캐시를 사용하므로 직접 호출하지 않는다.
조회 파라미터·커서 형태를 재사용하며 파서·인증·필드 계산은 기존 함수를 호출한다.

## 실행

호스트의 별도 worktree에서 실행한다. primary venv를 변경하거나 tenant를 부팅하지 않는다.

```bash
cd /home/deploy/.local/state/tos/measure/wt-cp3-pr1
PYTHONPATH=. /home/deploy/project/kis_unified_sts/.venv/bin/python \
  -m tools.tos_cp3.minute_probe --config config/tos_probes/cp3-pr1-20261012.yaml
# 위는 dry-run. 네트워크 허용은 --confirm 을 추가한다.
```

호스트 user systemd timer `tos-cp3-pr1-20261012.timer`는 **2026-10-12 08:44 KST 단 1회**를
예약한다. 측정은 08:46–15:46 KST이며 15:30 이후에는 successor 발견 후에도 추가 offset을
조회해 마감 응답을 남긴다. 날짜가 다르거나 종료 시각 이후이면 거부한다. `Persistent=false`라
놓친 예약을 뒤늦게 실행하지 않는다. 호스트가 예약 시각에 켜져 있어야 한다.

```bash
systemctl --user status tos-cp3-pr1-20261012.timer
journalctl --user -u tos-cp3-pr1-20261012.service --no-pager
# 예약 취소
systemctl --user disable --now tos-cp3-pr1-20261012.timer
```

## 증거와 판정

출력: `~/.local/state/tos/measure/cp3-pr1-20261012/` (0700, 파일 0600).
공용 `dotenv_guard.read_explicit_dotenv`를 통해 지정된 `.env.real`의 실전 키 두 개만 읽고,
hermetic 실행에서는 파일을 읽지 않는다. 앱 키 지문별 별도 토큰 캐시를 사용한다.
시세 GET은 method/TR/path 허용 목록으로 한정된다. OAuth 토큰 발급은 기존 인증 모듈의 POST다.
계좌·요청 헤더·토큰·응답 msg1을 증거에 저장하지 않는다.

- M1: `requests.jsonl`의 원시 `output2` 행과 요청 종목. 종목은 기존 mini 월물 해석기로 1회 선택한다.
- M2/M2b: `boundary-samples.json` + 원시 요청 기록. 분 경계 +1/+5/+15초의 첫 관측은 지연의
  **응답 수신 시각 상한과 직전 부재 요청의 시작 시각 하한 사이 구간**이며 연속 감시의 정확한 도착 시각이 아니다. 모두 부재이거나 지연 때문에 offset을 놓친 분은
  검열·누락 표본으로 남긴다. `delta_G`는 자동 확정하지 않는다. 장후 검열·에러·마감 원시 행을 확인해 도출한다.
- M3: `m3-seed.json`, `m3-full-day.json`. 기존 `produce_bars`를 각 3회 재실행한다.
- M4: `seed-summary.json`(페이지 호출 수·밀도·창 충족·과거 Parquet 차이),
  `m4-today-parser.json`(단일 분씩 파싱 vs 전일 파싱 차이). 레퍼런스가 없는 날은 비교 불가로 적는다.
- `sha256.json`: 종료 시 생성하는 증거 파일 지문. 에러 시 `abort.json`을 남기고 성공 판정을 내리지 않는다.

**측정을 놓치지 않도록 M1/M2/M2b를 먼저 수집하고 장후 시드 조회·M3/M4를 수행한다.**
새 월물의 과거 밀도가 부족해 시드 확보가 실패해도 이미 수집한 분 경계 관측·당일 전체 파싱 비교는 남는다.
로컬 사전 조사: A05611 저장 봉은 전체 277개, 09-28~10-08 구간 206개이며
저장된 모든 날짜가 330봉 미만이다. 이는 REST 재조회 전의 로컬 관측이며 시드 충족을 보장하지 않는다.
후속 분석이나 재실행은 기존 출력 디렉터리를 덮어쓰지 않고 새 경로를 지정한다.
이 프로브는 PR-2 생산자 또는 첫 genesis를 구현하거나 승인하지 않는다.

## 콜드 백업 — 운영자 직접 조치

실측 crontab의 `cold-backup-cp3-long`(18:20), `cold-backup-cp3-short`(18:40)은
둘 다 `COLD_TARGET_BORN_ON=2026-10-12`이고 tenant 잎은 아직 없다.
첫 genesis 날짜가 정해지기 전에는 **10-12 18:20 전 두 줄을 임시 주석 처리**하는 것을 권한다.
계획 §7의 지시: "에이전트는 호스트 crontab 을 바꾸지 않는다."

```bash
crontab -l > "$HOME/.config/kis-probes/crontab-before-cp3-born-on-20261012.txt"
crontab -e
# 끝의 주석이 cold-backup-cp3-long / cold-backup-cp3-short 인 두 줄 앞에 # 추가.
crontab -l | rg 'cold-backup-cp3-(long|short)'
```

기존 상주 `cold-backup-nightly` 18:00 줄은 다른 대상이다.
첫 genesis가 확인되면 해당 tenant 줄을 되살리고 BORN_ON을 그 첫 부팅일에 맞춘다.
