## E3 — 전수 스윕 (대조군 내장) : 내 스윕이 얼마나 놓쳤는가

**도구가 존재하는 이유**: 내 스윕이 두 번 연속 실패했다.

```
1회  grep -v "UNBOUND" 가 BOUND/BLOCKED/UNBOUND 줄을 통째로 걸러 BOUND 잔존을 놓침
2회  kind=WORK 패턴만 찾아 NORMATIVE 단독·WORK화 형태를 놓침 (DEF-9)
```

두 번 다 **패턴이 대상보다 좁았고 "0건"을 통과로 읽었다.** 그래서 이 도구는
**각 패턴마다 알려진 인스턴스를 심어 검출되는지 먼저 확인**하고, 대조군이 실패하면
그 패턴의 결과를 폐기한다.

### 결과 (전 패턴 대조군 통과)

| 패턴 | 잔존 | 내 직전 스윕 |
|---|---:|---:|
| 구 U-1a 전칭 조건 | **1** (:2199) | 0 (놓침) |
| 폐기 `kind` 어휘 | **10** | 3 |
| 거짓 L1 전칭 | 1 (:1200) | 1 |

**내 좁은 패턴은 3건, 대조군 있는 스윕은 10건을 찾았다.**

### 이 도구의 한계 — 과다 보고 (정직하게 기록)

`kind` 10건 중 상당수는 **역사 서술**이다:

```
:2287-2291  "v1.7의 LIMIT/WORK/NORMATIVE 는 배타적이지 않았다 …"  ← 폐기 근거 설명
:2347       스파이크 대조표의 뮤테이션 라벨                        ← 실행 기록
```

진짜 활성 잔존은 **:1792(T-61)·:1978(§11 종료조건)** 과 §13.6.3~4 의 재분류 문장이다.
`거짓 L1` 1건(:1200)도 `>` 인용 블록 안이라 **v1.5 원문을 역사로 인용한 것**이다.

행 단위 역사 제외 규칙(`HISTORY`)이 **인용 블록과 설명문을 구별하지 못한다.**
이는 도구의 알려진 한계이며, **0건을 신뢰할 수 있게 만드는 것**이 목적이지
잔존 목록을 그대로 처분 목록으로 쓰라는 뜻이 아니다.

→ v1.9 처분: :1792·:1978 및 §13.6.3~4 의 활성 문장을 교정. 역사 서술은 유지.
