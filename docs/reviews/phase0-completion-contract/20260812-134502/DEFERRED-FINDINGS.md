## DEF-9 (확증) — 폐기한 `kind` 어휘가 완료 계약과 대조군 3곳에 살아 있다

v1.8은 §13.6.1에서 `LIMIT`/`WORK`/`NORMATIVE` 3분류를 **폐기**하고 직교 2필드
(`normative_ref` / `closable`)로 교체했다. 그런데:

| 위치 | 잔존 |
|---|---|
| **:1978 §11 종료조건** | "모든 **`NORMATIVE`** 항목이 `blocks_gate` 를 명시 (U-8)" |
| **:1791 T-58** | "`kind`를 **`NORMATIVE`**에서 **`WORK`/`LIMIT`**로 낮추거나…" |
| **:1792 T-61** | "`blocks_gate=G2` 행을 **`WORK`화**(=`normative_ref` 공란)했을 때" |

### 귀결

- **§11(완료 계약)이 존재하지 않는 필드 값을 조건으로 건다.** v1.8의 규칙은
  "`normative_ref` 가 비어 있지 않은 항목"이다. `NORMATIVE` 라는 값은 더 이상 없다.
- **T-58은 구성 불가다.** `kind` 필드가 없으므로 "`NORMATIVE`→`WORK` 로 낮추는"
  뮤테이션을 만들 수 없다.
- **T-61은 어휘가 섞였다.** 새 기제(`normative_ref` 공란)와 폐기 라벨(`WORK`화)이
  한 문장에 있다.

## 내 스윕이 왜 놓쳤나 — 검증 패턴이 검증 대상보다 좁았다

v1.8 개정 후 나는 이렇게 스윕했다:

```bash
grep -n "kind=WORK\|kind = WORK\|kind=LIMIT" "$D" | grep -v "..."
# → "없음"
```

**`kind=` 접두를 붙인 패턴만 찾았다.** 실제 잔존은 `NORMATIVE` 단독,
`WORK`/`LIMIT` 단독, `WORK`화 같은 **접두 없는 형태**였다. 패턴이 대상보다 좁았으므로
스윕은 "없음"을 반환했고 나는 그것을 통과로 읽었다.

**이는 S-8("식별자 리터럴 grep 으로 개념 범위를 확정하지 않는다")의 위반이며,
S-8을 문서 census 에는 적용하고 내 검증 스윕에는 적용하지 않은 것이다.**
직전 회차에도 같은 형태가 있었다 — `grep -v "UNBOUND"` 가 `BOUND/BLOCKED/UNBOUND`
줄을 통째로 걸러내 `BOUND` 잔존을 놓쳤다.

```
S-15 는 v1.8 에서 "스파이크·측정 스크립트까지" 확장됐다.
같은 확장이 **검증 스윕 자체**에도 필요하다:
    스윕 패턴은 폐기 대상의 **모든 표기 형태**를 덮어야 하고,
    "0건"은 패턴이 옳았다는 증거가 아니다 — 대조군(알려진 잔존 1건을 심어 검출되는지)
    없이 0건을 통과로 읽으면 스윕은 공집합 검사가 된다
```

**이것이 T-3c 공집합 결함(v1.3.13)과 같은 형태다** — 그때는 문서의 테스트가 공집합을
검사했고, 이번엔 내 스윕이 공집합을 검사했다.

## 처분 방향 (판정 후 확정)

문구 교체로 끝내면 일곱 번째가 예약된다. 다만 **규칙을 또 추가하는 것도 답이 아니다** —
S-1~S-15가 여섯 번 연속 이 클래스를 막지 못했다.

이번 회차의 새 사실 하나는 기록해 둔다: **스파이크가 이 클래스를 한 번 잡았다.**
`blocks_gate` 소비 부재는 문서를 읽어서가 아니라 **게이트 판정을 실행해서** 드러났다.
선언층/평가층 간극은 정의상 **평가를 실행해야 보이는 결함**이므로, 종이 위 스윕으로는
구조적으로 잡히지 않을 가능성이 높다.

→ 심판 판정과 함께 **"검증 스윕을 실행 기반으로 전환"**(어휘 폐기 시 실제 파서·검사기를
돌려 잔존을 검출)을 처분 후보로 올린다. 다만 그 검사기가 아직 없다는 것이 이 트랙의
근본 제약이며, 그것이 스파이크를 도입한 이유이기도 하다.
