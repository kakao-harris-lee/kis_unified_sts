# 동결 중 이연된 지적 — v1.4 재심 판정 후 처분

## 동결 상태

```yaml

plan_scope_digest: f706f5df5410ade9070418a6fc5770121525d07bde7b8baec437ab263a9a48e7
freeze_verified_at_deferral: f706f5df5410ade9070418a6fc5770121525d07bde7b8baec437ab263a9a48e7  # 일치

```

**이 지적들은 문서에 반영하지 않았다.** 재심이 in-flight이며, 편집하면 결속이 깨진다 —
v1.3 대상 심판 4회 연속 실패의 원인이 정확히 그것이었다. 운영자 지시("무한 루프에
빠지면 안돼 / 다음 세션 권고대로 진행")에 따라 **판정 수령 후 일괄 처분**한다.

## DEF-1 (치명) — `floor(e)` 도입이 Phase 0 종료조건을 도달 불가로 만든다

**Stop 게이트 원문**: "v1.4 makes Phase 0 unachievable"

### 실측 근거

```
:758   floor 규칙   레벨집합 ∩ {3,4,5} ≠ ∅  → + {FAULT}
       (Part-1 실측: EV-L3 계열이 372행 중 다수. PASS/READY 81행에도 포함)
K-3    FAULT 는 정규 fault 시나리오 레지스터 부재 → 항상 existence=UNVERIFIABLE (UNCHK-003)
:958   FWD-a    "UNVERIFIABLE 쌍은 **FWD-a 충족으로 계수되지 않는다**"
```

### 귀결

`PASS`/`READY` 81행 중 레벨 3 이상인 행은 `floor`에 의해 `FAULT` 쌍을 갖게 되고,
그 쌍은 구조적으로 `UNVERIFIABLE`이며, FWD-a는 그것을 충족으로 세지 않는다.
→ **해당 행의 FWD-a는 영원히 불충족**
→ §11 종료조건 "phantom owner/row 0" **도달 불가**

### 결함 클래스

**v1.3.1에서 고친 IC-5의 재발이다.** 당시 K-5(`PLANNED_UNASSIGNED`는 required_kinds를
충족하지 않는다)와 종료조건이 충돌해 "미매핑 0"이 도달 불가였고, FWD-a/FWD-b 분리로
닫았다. v1.4는 **하한을 도입하면서 "누락이 침묵에서 계수로 바뀐다"는 이득만 검토하고,
그 계수가 FWD-a 충족 판정에 무엇을 하는지 확인하지 않았다.**

§8.2 S-5("새 표현 수단이 기존 계약과 충돌하지 않는지 전수 대조")를 `floor` 도입에
적용하지 않은 결과다.

### 처분 방향 (판정 후 확정)

FWD-a의 충족 판정에서 `UNVERIFIABLE` 쌍을 **불충족이 아니라 판정 제외**로 다뤄야
한다 — 즉 FWD-a는 *검증 가능 kind의 쌍*에 대해서만 충족을 요구하고, `UNVERIFIABLE`
쌍은 §13 계수로만 반영한다. 단 그렇게 하면 "UNVERIFIABLE만 남은 행"이 공허하게
통과하므로, K-8의 SUBSTANTIVE 요구가 그 경로를 막는지 재확인이 필요하다.

**S-2를 적용해 교정안 자체의 우회로를 먼저 구성해 볼 것.**

## DEF-2 (high) — `UNDECIDED` 탈출구가 한 단계 위로 옮겨갔을 뿐이다

**Stop 게이트 원문**: "leaves the `UNDECIDED` escape hatch open"

### 실측 근거

v1.4 §7.4는 처분을 검사기 파생으로 바꿔 **라벨링 재량**을 제거했다. 그러나:

```
저작자 입력 = "의존 키" 1개
키를 공급하지 않으면 → 검사기가 UNDECIDED 부여
UNDECIDED → §13 등재 (U-6)
:1796  U-1  "Phase 0 완료 조건은 이 레지스터에 등재된 축을 요구하지 않는다"
→ 완료조건에서 제외
```

**입력 재량이 남아 있다.** "키를 공급하지 않는다"는 선택이 여전히 저작자의 것이고,
그 결과는 v1.3.13과 동일하게 완료조건 제외다.

v1.4 §7.4는 "저작자가 '이건 판정 불가'라고 선언할 경로가 사라진다"고 썼으나,
**선언 대신 침묵으로 같은 효과를 낸다.**

### 처분 방향 (판정 후 확정)

키 공급 실패를 무료로 두지 않는 장치가 필요하다. 후보:
- 7개 사이트는 소수이므로 **키 공급을 완료조건으로** 하고, 공급 불가는 운영자 승인 대상
- 또는 `UNDECIDED` 개수에 대한 상한을 운영자가 정하고 초과 시 차단

어느 쪽이든 **"세어서 보여주면 된다"로는 닫히지 않는다** — U-1이 등재 축을
완료조건에서 빼는 한, 등재는 면제 경로다. 이는 v1.3.13 심판 finding #1이 §13 전체에
대해 지적한 것("레지스터가 누락 방어보다 제외 정당화로 쓰인다")과 같은 축이며,
§13.5는 그 지적의 **U-2 측면만** 닫았고 **U-1 측면은 닫지 않았다.**

## 재심을 중단하지 않는 이유

DEF-1이 치명적이므로 현재 심사 대상에 알려진 결함이 있다. 그럼에도 재심을 취소하지
않는다:

1. 심판의 가치는 이 한 결함이 아니라 **6건 처분 전체에 대한 판정**이다
2. 취소·재디스패치는 v1.3 대상 4회 실패와 같은 패턴이며, 운영자가 종료시킨 루프다
3. DEF-1·DEF-2가 기록됐으므로 판정과 함께 일괄 처분하면 된다

판정이 DEF-1을 독립 발견하면 그 자체가 심판 레인의 유효성 증거이고, 발견하지 못하면
이 기록이 보완한다.
