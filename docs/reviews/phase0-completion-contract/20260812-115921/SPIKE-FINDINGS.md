## Q1 — **정정**: T-61 은 세 해석 모두에서 **구성 가능**하다

### v1 이 무엇을 잘못했나

v1 스파이크는 G2 술어를 이렇게 하드코딩했다:

```python
not_impl = sum(1 for r in rows if r.status == "NOT_IMPLEMENTED")
if not_impl: reasons.append(...)      # 490행 중 409행 → 항상 참
```

**이것은 설계의 G2 가 아니라 내가 고른 해석이다.** 설계 §4.2.1 의 G2 술어는 세 행이고,
그중 기계 검사 가능한 것은 **(b) "미실행 항목을 임의 `PASS` 로 바꾸지 않음"**(어휘
무결성)이다. (a)는 `부분`, (c)는 `NOT_MACHINE_CHECKABLE` 로 표시돼 있다.

"409행이 `NOT_IMPLEMENTED`" 와 "(b) 위조 `PASS` 가 있다"는 **다른 명제**다.
전자는 항상 참인 지배 사유이고, 후자는 현재 **위반 0건 → MET** 이다.

### 재검증 결과

```
변형                     소비X      소비O      뮤테이션    T-61 구성 가능?
A_all_rows             NOT_MET   NOT_MET   NOT_MET    가능 (사유 집합만)
B_vocabulary_only      MET       NOT_MET   MET        가능 (verdict 뒤집힘)
C_required_subset      NOT_MET   NOT_MET   NOT_MET    가능 (사유 집합만)

상태 어휘 이탈 실측: 0건  → 변형 B 의 (b)는 현재 MET
```

**세 변형 전부에서 T-61 은 구성 가능하다.** 그리고 **§4.2.1 이 실제로
`CHECKABLE` 로 표시한 술어(변형 B)에서는 지배 사유가 아예 없고 verdict 가 깨끗하게
뒤집힌다** — `MET → NOT_MET → MET`.

### v1 이 자기 데이터와도 모순됐다

v1 스파이크의 출력에는 이미 관측 가능한 차이가 **찍혀 있었다**:

```
[소비 경로 도입]           사유 3건 (register 2건)
[뮤테이션 NORMATIVE→WORK]  사유 1건 (register 0건)
```

그런데 v1 findings 는 "T-61 구성 불가"라고 썼다. **자기 출력이 반증하는 결론을
발표했다.**

### 정정된 결론

| v1 주장 | 정정 |
|---|---|
| `blocks_gate` 는 G2 에서 관측 불가 | **거짓.** 변형 B 에서 verdict 뒤집힘, A·C 에서 사유 집합 관측 |
| T-61 구성 불가 | **거짓.** 세 변형 모두 구성 가능 |
| 지배 사유가 존재한다 | **내가 만든 것.** §4.2.1 의 `CHECKABLE` 술어에는 없다 |

**여전히 유효한 것**: 사유 집합 멤버십을 관측량으로 삼는 것은 **세 변형 모두에서
작동하는 견고한 선택**이다. 다만 근거가 "verdict 관측이 불가능해서"가 아니라
"**G2 술어 해석이 아직 확정되지 않았고, 어느 해석에서도 작동하기 때문**"이다.

→ v1.8 처분 방향(정정): U-8 의 관측량을 사유 집합 멤버십으로 두되, 이유는
   **해석 미확정에 대한 견고성**이라고 쓴다. "verdict 로는 관측 불가"라고 쓰면 거짓이다.
   그리고 **§4.2.1 G2 의 세 술어 중 무엇이 실제 판정에 들어가는지**가 미정의라는 것이
   이번에 드러난 별도 결함이다(신규 등재 대상).

## 이 스파이크가 저지른 결함 — 조사 대상과 같은 클래스

**나는 조사하려던 바로 그 결함을 스파이크에서 반복했다.**

```
설계의 반복 결함  선언층에 기제를 만들고 평가층 연결을 확인하지 않는다
스파이크의 결함   지배 사유를 하드코딩하고 그것이 설계에서 나왔는지 확인하지 않는다
```

둘 다 **미기술 가정에서 결론을 만들고 실측처럼 제시**했다. S-15("발표 수치는 발표한
규칙으로 재계산해 대조한다")가 문서에 대한 규율인데, **스파이크 산출물에는 적용하지
않았다.**

→ S-15 의 적용 범위를 문서 수치에서 **모든 산출물(스파이크·측정 스크립트 포함)**로
   넓혀야 한다. 측정 도구가 측정 대상보다 검증이 느슨하면 그 측정은 증거가 아니다.

**Stop 게이트가 이것을 잡았다.** 저작자 자신은 자기 출력이 결론을 반증하는데도
발표했다 — 독립 채널의 값어치가 다시 실증됐다.

## 잔여 (이 스파이크가 답하지 않은 것)

- §4.2.1 G2 세 술어 중 **무엇이 실제 판정 입력인가** — 이번에 드러난 미정의
- `required_kinds` 실제 파일의 스키마·작성 주체 (in-memory 합성이었다)
- `kind` 3분류의 배타성 — 정의 문제이지 데이터 문제가 아니다
- `owner_track` 허용 집합 문법
- G1/G3 의 술어 구성
